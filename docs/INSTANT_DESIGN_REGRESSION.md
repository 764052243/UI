测试前锁定：001/002身份、仓库 main 提交SHA、项目提示词是否已在设置生效、使用的模型/推理档位（以界面显示为准）、附件及已认可版本、目标画幅与页面列表。不能访问同一输入或切换档位就注明“不可比”，禁止编造提升率或质量稳定结论。

每个用例记录：角色｜用例编号｜日期｜档位｜引用基线（图片/文件版本）｜目标/非目标变更｜Q0需求识别｜Q1冻结区域｜Q2视觉与业务｜Q3文件/运行证据｜用户验收｜状态（通过/失败/未测）｜证据。**关键红线违反直接判失败，不用其他项目得分抵消**。视觉观感的主观判断需由用户确认。

## 二、设计行为回归案例

| ID | 角色 | 输入/任务 | 必验项（关键红线） |

## 三、三种状态不可混淆

- **规范静态验证**：文件、路径、角色入口、文档版本和案例编号存在，意味着“规则可读”，不代表 UI 画面质量通过。
- **实际对话/图像/源码验证**：使用001或002的真实会话并有输出证据，才能声称“该场景在该档位通过”。
- **用户认可**：仅用户对指定页面/版本确认后，才能成为认可视觉基线。一个档位测试通过不代表其他档位或未来所有任务都有质量保证。
