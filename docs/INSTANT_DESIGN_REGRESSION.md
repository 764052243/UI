# UI设计师｜即时模式设计质量回归用例 V1.2

> 本文档定义**待执行**的跨推理档位对照用例，不是测试报告。案例是通用文本，不包含用户私有截图或具体业务资产。执行者需为每个场景补上可使用的真实授权素材及实际观测记录。

## 一、操作方法与对照记录

测试前锁定：实际执行员工身份（001/002/003等）、仓库 main 提交SHA、项目提示词是否已在设置生效、使用的模型/推理档位（以界面显示为准）、附件及已认可版本、目标画幅与页面列表。不能访问同一输入或切换档位就注明“不可比”，禁止编造提升率或质量稳定结论。

每个用例记录：角色｜用例编号｜日期｜档位｜引用基线（图片/文件版本）｜目标/非目标变更｜Q0需求识别｜Q1冻结区域｜Q2视觉与业务｜Q3文件/运行证据｜用户验收｜状态（通过/失败/未测）｜证据。**关键红线违反直接判失败，不用其他项目得分抵消**。视觉观感的主观判断需由用户确认。

| VQ-15 | 001/002/003等获授权设计师 | 已认可页面经过至少五轮短反馈，依次改位置、几何、局部色彩、禁止图形和输出方式 | 每轮维护 `accepted_baseline / current_candidate / pending_constraints / frozen`；新要求只更新相关属性，先前未通过项、否定项和冻结区仍有效；不能用最近失败候选覆盖认可原稿。逐轮输出真实差异证据；没有用户明确整图认可不自动升级基线。 |
| VQ-16 | 001/002/003等获授权设计师 | 用户说“按钮不突兀了”，但上下文存在“希望更明显”与“降低抢眼”两种反向解释 | 结合上下文识别需求是“降低干扰且保持可辨认”还是“需要增强显著性”；如确有方向冲突仅问一个必要问题，收到用户纠正后更新尚未通过属性，不将模糊反馈当整图认可，不改变位置或已锁定结构。 |
| VQ-17 | 001/002/003等获授权设计师 | 用户仅要求某侧栏纹理的背景范围和淡化方向，文字、图标和其他页面已认可 | 只修改指定区域/属性；实际比对背景上缘与下缘明度、Alpha/纹理范围，目标区域外及邻近文字逐像素/DOM冻结；不能用整体重生成、改别处颜色或换皮被否定纹路来掩盖范围问题。 |

| VQ-19 | 001/002/003等获授权设计师 | 用户要求去除新增的外发光，但保留原件已有柔和光影、实体尺寸与清晰度 | 区分原有合法柔光和候选新增脏光；核对Alpha>0与主体核心框、可见像素和金样ROI，去新增光不能通过缩小主体/剪掉合法柔光蒙混；用户若明确要求两状态都无光，则对两个状态统一执行，并验证体积/形状保真。 |

### VQ-15～20 视觉诊断能力附加回归（待真实 Instant 实测）

以下 VJ-A～D 是对现有 VQ-15～20 的**可执行子场景**，不新增同义 SKILL、不预设固定色值或像素位置。每项必须保存带版本身份的认可图与候选、原话或匿名化等价输入、允许/冻结属性、实际最终文件、逐轮目标与非目标对比；明确标注几何实测与用户/独立视觉评审的**不同证据来源**。仅写“已经理解/感觉更好”属于FAIL。

| 子场景 | 适用原用例 | 连续输入/反例设计 | 通过与失败判据 |
| --- | --- | --- | --- |
| VJ-A | VQ-16、VQ-19 | 先要求操作控件“明显些”，后要求“减轻存在感”；保持其可操作性、原布局和周围业务内容 | 能指出视觉焦点、符号可读性、底板反差/框线/光效中哪一因素造成突兀，仅动获授权最小变量；全页原尺度下不抢业务主内容，局部仍清晰可辨；只把整件缩小/淡到认不出、只随机换色，或擅自定版均FAIL。主观是否协调由独立视觉评审/用户确认。 |
| VJ-B | VQ-15、VQ-17 | 用户先说某区域“太素”，随后否定新增纹路“突兀”，但已认可该区域配色和边界范围 | 区分造型/材质层次不足与纹路形态、密度、方向、对比或接缝问题；保留已认可色域与背景范围，不再换色复用被否定的纹路形态；生成的局部100%和全页前后对照能指出具体修复。把“太素”默认解释为高饱和/添加波纹或牵连其他区域为FAIL。 |
| VJ-C | VQ-15、VQ-17、VQ-18 | 局部背景先获认可，后只改旁边控件；再要求仅控件符号按“当前的0.75倍”缩小、接着调整该符号颜色 | 局部背景以独立ROI/属性锚点保留，不把整页候选升级为基线；符号缩放明确当前有效版本与锚点、真实可见尺寸按当前值乘0.75核对，底板/布局冻结；下一轮再说“0.75倍”时不得按初版重算；颜色仅改指定符号层。任一累计要求丢失或局部认可范围回退即FAIL。数值0.75只属测试输入，不是全局设计默认值。 |
| VJ-D | VQ-16、VQ-17、VQ-18、VQ-19 | 两组故意构造的候选：①尺寸/净空/冻结全部测量PASS但相邻材质或对比明显突兀；②视觉评审觉得顺眼但尺寸、参照净空或冻结区故意FAIL | ①必须标“几何通过、视觉未通过/待独立复评”，不可报最终完成；②必须标“视觉可能通过、工程约束失败”，不可报完成。几何按真实文件/DOM测，视觉需有同尺度ROI+全页审图证据及独立评审/用户结论。不能用主观评分替代指标，亦不能用指标替代美感。 |

**执行记录字段**：场景ID｜实际员工/档位及项目设置版本｜认可基线/认可局部ROI身份｜每轮用户反馈与更改属性｜目标测量值/前后像素ROI｜冻结区结果｜局部100%/相邻组件/全页原尺度三视图｜用户或独立视觉评审结果｜通过/失败/未测及证据。以上场景目前**全部待真实 Instant 会话验证**；003提案内容本身及静态文档检查不构成模型视觉判断能力通过。

**VQ-15～20 实施证据（003经验匿名化复盘）**：每轮保留认可原件身份、明确反馈原话或不含敏感信息的等价任务、变更对象与未通过项、所用工具及真实产物、同尺寸差分/Alpha框/镜像RGBA检查结果、聊天预览与下载是否同版、用户是否认可。案例中的镜像和阈值只是**适用时的精确证据方法**，并非所有状态PNG必须镜像、每个图标必须有固定核心面积，也不允许为了通过指标裁掉合法光晕。当前新增案例均为**待真实Instant会话实测**；003历史报告的一个已测镜像案例不能外推为Instant跨档位通过。

## 三、三种状态不可混淆

- **规范静态验证**：文件、路径、角色入口、文档版本和案例编号存在，意味着“规则可读”，不代表 UI 画面质量通过。
- **实际对话/图像/源码验证**：使用对应已获授权设计师的真实会话并有输出证据，才能声称“该场景在该档位通过”。
- **用户认可**：仅用户对指定页面/版本确认后，才能成为认可视觉基线。一个档位测试通过不代表其他档位或未来所有任务都有质量保证。
