# UI设计师｜PNG 图标紧裁、居中与视觉保真验收 V1.0

> **负责人**：UI设计师000（规范与工具）。**执行者**：001/002（实际UI资产与HTML）。目标不是“切出PNG就算完成”，而是**每个可复用图标都必须去除多余透明空白、内容居中、边缘无瑕疵，且在HTML中忠实呈现用户认可的样式**。
>
> **当前用户截图的边界**：这是 Windows 文件夹缩略图而非每个 PNG 文件内容。可以看到不同缩略图中的图形比例和位置不统一；**不能仅凭截图断言每个 PNG 的实际 Alpha、精确空白像素数或是否有不透明背景**。必须取得具体原 PNG 做文件级检查。未经明确授权，不把用户素材上传公共仓库。

## 一、把图标的“裁切”区分为四层

| 层级 | 实际要求 | 常见伪通过 |
|---|---|---|
| A 图标元素 | 真正独立的图形，不带导航文字、截图白底/黑底、旁边按钮 | 一整块黑色按钮截图，文件名叫 `icon` |
| B PNG 文件 | 图形和所有发光/底座有效像素完整；**裁掉多余透明外边**，透明包围框与画布居中 | 128×128 文件中图只有20×20且偏到左上角 |
| C 前端显示槽 | HTML/CSS 图片容器有明确宽高，图标 `object-fit:contain`、容器 flex/grid 居中、不拉伸 | 图文件自身偏心，用一堆 CSS left/top 修饰，切换尺寸后又错位 |
| D 认可视觉金样 | 原图的形体、厚度、阴影、光源、对比度、尺寸和位置与HTML实际渲染一致 | PNG透明、有文件、有HTML，但图标变扁平或大小和原图不一致 |

A/B/C/D **都要满足**。自动工具主要证明B的一部分；不可以把“Alpha校验通过”宣传为图标从原图精确抠出或视觉质量通过。

## 二、PNG 规范及自动检测结果

用 `scripts/normalize_ui_icons.py` 可对目录所有 PNG 执行：

```bash
python -m pip install Pillow

# 检测当前源图，生成结构化报告；失败图标阻断交付
python scripts/normalize_ui_icons.py delivery/assets/icons \
  --report working/icon-trim-audit.json

# 不覆盖源图，将去空白后的候选输出到工作目录
python scripts/normalize_ui_icons.py delivery/assets/icons \
  --output-dir working/icons-trimmed --padding 2 \
  --report working/icon-trim-output.json

# 人工逐一对照金样/原PNG，确认不裁内容后，用合格文件替换对应 delivery/assets/icons
python scripts/verify_ui_delivery.py delivery/ --zip delivery.zip
```

**默认有效像素定义**：Alpha 大于0（包括极弱光晕）；按该范围的包围框裁剪，四边默认各留 2px，**保持像素 RGBA 完全不缩放不变形**，旧文件保留。源图若是不透明矩形、存在残留黑底/白底、低清模糊或假图标，需要源稿提取/修复/重绘，**脚本不能凭空修复这些视觉问题**。

检查器按 PNG 短边自动计算容忍范围：允许最大透明边距 `max(2px,ceil(短边×4%))`，允许左右/上下边距差 `max(2px,ceil(短边×2%))`。超出直接 FAIL。该阈值用于**阻断明显冗余空白/偏移**，不保证图标在人眼看起来恰好居中。异常不允许通过改变报告数值、改小图标、粗暴增加 Alpha 阈值、裁掉原图光晕或调CSS硬顶来掩盖。

脚本输出 JSON 字段：`canvas`、`alpha_bbox`、`transparent_margins_ltrb`、`geometrically_centered`、`tightly_trimmed`、`manual_fidelity_review_required`；批处理模式记录 `before`、`after` 和输出路径。**全透明、不透明、损坏 PNG 和试图原地覆盖均失败**。

### HTML 图标容器（实现参考，不是用户界面默认设计）

```css
.nav-icon-slot {
  width: 32px;
  height: 32px;
  display: inline-flex;
  align-items: center;
  justify-content: center;
  flex: none;
}
.nav-icon-slot > img {
  display: block;
  max-width: 100%;
  max-height: 100%;
  width: auto;
  height: auto;
  object-fit: contain;
}
```

`32px` 只是代码示例，**以用户已认可金样中的真实尺寸和比例为准**。不可通过把所有不同造型图标强行拉到同一长宽来“对齐”；实际 CSS 插槽尺寸、图标可见大小和标签间距均需按金样验证。原图存在底托或大范围阴影的图标，其完整有效内容就是图标的一部分，不能错误裁掉。

## 二点一、图标虚化与缺半截的通用根因门禁（逐件执行）

**先分清两类失真，禁止混为“缩略图变模糊”**：

- **显示缩略图的软化**：文件管理器可能对图标生成低分辨率预览并二次插值。不能仅凭缩略图给出真实PNG的锐度数值；必须打开**实际PNG文件100%像素**，检查导出尺寸、RGBA、源文件与HTML的原生DPR。
- **真实PNG已经断裂/只剩一条边/半个符号**：通常涉及错误ROI、误分割、阈值抠图、源图本身不完整或被裁边，这与缩略图清晰度是不同问题。**任何图标缺少原形体必要笔画时一律不通过，即使Alpha包围框完全居中、透明度与文件尺寸合格。**
- **二次重采样的虚化**：以聊天缩略图、浏览器截图或文件夹预览作为源，裁出低分辨率图标后放大，再经过抗锯齿、模糊/羽化或CSS缩放，会丢失边缘高频细节。只有来自真正原生源层或矢量/可编辑源的导出，才有资格声明“高清”；不准在切图时靠加锐化声称恢复真实细节。

**分流工作法**：优先读取用户最后认可的原稿及可编辑SVG/PSD/Figma/原始图层；如果原先已有一份清楚、形体正确的独立PNG，应优先保留和复用它，**不能因为换了切图流程就重新从低清整体截图提取**。失真只是局部个例时不要重新生成其它已认可图标。无源层时按无PSD高保真重建流程逐图标复刻并验证，不把低清crop扩大成高清。

**可验证来源完整性（仅对真独立RGBA图层）**：已有[原生像素/完整视觉单元检查器](../scripts/audit_cutout_source_quality.py)可在plan某项增加`"integrity_mode":"lossless_isolated_layer"`与`"source_layer_path":"assets/source-icon.png"`。它逐一比较原独立图层与导出PNG的**完整可见RGBA**（允许平移和裁透明边；禁止内容丢失、重采样、平滑、变色）；失去半截、二次缩放、颜色被改会FAIL。**不适用于不透明整体截图、从背景抠图、SVG重新栅格化或AI重建**，那些必须按真实原图ROI和透明三底色人工/浏览器验收。没有可信源PNG时不能伪造`source_layer_path`或把这一检查标PASS。

**交付红线**：逐件提供原生实际PNG的100%预览、可信来源/生成方式、导出图真实像素与HTML显示DPR，明确“完整图形、可见笔画、锐度/颜色、透明边、HTML效果”是否都通过。**只输出文件夹缩略图或只看Alpha居中检查不能认定通过。**

## 三、每个图标的人工复核（逐一，不抽检）

在不改变原图设计的前提下，至少检查：

1. 同一 PNG 分别叠放在深色底、浅色底和透明棋盘底：Alpha 透明、黑白脏边、底色残留、低透明像素、图标轮廓、光晕完整度。
2. 原图金样 ROI 与独立图标的可见内容：轮廓、中心、笔触、体块、厚度、倾斜角、色彩及发光方向正确；**图标不能因为切空白变成另一个形状或丢底座**。
3. HTML 真正渲染：图片槽、菜单标题和底部状态条的相对位置正确；不同尺寸不拉伸，图标与标签视觉居中。
4. 保存资产前后对比：归一化工具只能平移 PNG 的完整 Alpha 包围框，不能无声改色、模糊或重采样；需要重绘的项单独标记来源 `reconstructed` 并核对用户认可金样。
5. 目录里**每一个图标**都执行检查；只要一个关键图标严重变形或偏心，就标该资产未通过，不能以“整页整体像”代替。

## 六、V2.0：黑底残留优先于Alpha居中（2026-11-12反馈）

**故障根因**：部分图标在用户截图中仍有大片深色矩形底板或视觉主体偏移。旧检查只判断 `Alpha>0` 的总体包围框；当**一块黑底本身就是不透明像素**时，程序会把黑底也算成图标主体，裁边和“居中”可能全部通过，**真正前景符号反而没有被单独提取**。

**新规定**：`assets/icons` 必须优先提供可独立复用的**前景符号**；原图中的黑色面板、圆形徽章背景、业务立体底托需按用户认可基线分开输出到 CSS/背景或 `assets/components`。之前“底托不能裁掉”是指**不能丢失原设计元素**，不是允许将所有黑色底板永久烘焙到前景 PNG 里。用户额外要求“完整复合图标”时可另交完整组件，但不能替代单独图标。

检查顺序改为 **B0：区分前景/背景/底托 → B1：三底色实图检查 → B2：源层提取或可追溯重建 → B3：前景PNG紧裁/居中 → B4：HTML复合还原**，然后再复验 I0～I5、F0～F5、S0～S5。

### 工具能做什么、不能做什么

`scripts/normalize_ui_icons.py` 的**矩形底色检测**主要针对“透明图层中仍嵌有较完整的不透明黑/白矩形”这类高风险情况。对明显深色中性矩形且四周边线近似不透明，自动 **FAIL**；此工具不自动删除黑色，不把误检测修复成背景穿孔。完整背景不一定是矩形、边缘可能有强光/渐变，因此**通过检测不代表真正抠干净**。

```bash
# 每张图标必须由实际PNG生成三底色可见对照（输出到源目录外）
python scripts/normalize_ui_icons.py delivery/assets/icons \
  --report working/icon-qa.json \
  --contact-sheet working/icon-review.png
```

即使脚本报告 `PASS`，人工仍必须**逐件检查**棋盘底、白底、深底中的背景残留、黑白脏边、前景偏心；按第二张已认可的效果图核对图形、颜色、光晕、实体厚度，并在 HTML 真实位置叠加独立底托后再次对照。文件夹缩略图不能替代此证据。
