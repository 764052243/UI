# UI设计师｜切图资产判定、背景生成与边缘质量 V1.0

> 适用：001/002要求对认可图进行“切图＋HTML还原＋ZIP”时，与 `skills/semantic-asset-export/SKILL.md` 联动。**本规范不是要求把页面上的一切都导出为PNG**，而是只导出需要位图保真的、可被前端复用的视觉图层。
>
> 用户本轮对照：认可的大屏整体图（含导航、中央地图、立体底座和底部业务模块）、独立导航截图，以及 `deco_business_*_plinth.png`、`deco_kpi_*_disc.png`、`stage_3d_plinth_masked.png`、`icon_business_*.png` 等资源文件夹截图。**目前能判断的是角色划分、素材完整度和边缘质量存在风险，无法从文件夹缩略图定量证明Alpha、真实完整性或逐像素毛边程度。**

## 一、根因：以前将“背景要分离”误执行为“所有底色都切成PNG”

三种错误必须分别阻断：

1. **错误切出**：可以用CSS稳定实现的纯黑、圆形衬底、渐变圆盘、规则按钮底色，被单独裁成几十张PNG，增加重复、缩放瑕疵、像素密度不一致和HTML维护成本。
2. **错误缺失**：复杂中央地图、分层3D底座、反光、霓虹边缘本应保留视觉图层，却只从扁平截图蒙版切出“一半”，或变成纯黑图、黑色矩形残影。
3. **错误扣图**：直接裁矩形、低质量颜色抠图、反复重采样导致锯齿、杂色轮廓、黑白边、光晕被截断，最终PNG虽透明、尺寸合规却无法还原认可画面。

## 二、裁切前的“要不要PNG”决策树（先决定，后动手）

**P0 语义优先；只输出需要的素材，不强制资产数量。**

| 元素或案例 | 正确角色 | 为什么 | 默认处理 |
| --- | --- | --- | --- |
| 顶栏业务名称、数字、时间、标题、按钮标签 | `html_text` | 文本可选中、可动态更新 | HTML DOM，不切PNG |
| 简单纯色/深色大屏底、面板黑色块、圆形徽章暗色衬底 | `css` | 稳定可控，易于响应式和对齐 | CSS背景/伪元素，不切PNG |
| 规则导航按钮底（六角切角/橙色渐变） | `css` **优先**；复杂不可还原时`component` | 颜色、描边和切角通常可由CSS实现 | 与金样对照；仅真实复杂纹理才切PNG |
| 用户明确要求的独立小图标符号 | `icon` | 单一业务语义、复用及状态切换 | 前景RG‌BA透明PNG，不含圆盘/卡片底 |
| 底部业务5个“蓝色3D底托” | `component`，但可复用底托只需**一份** | 视觉装饰、不是业务图标；裁出不完整或五份一样会浪费 | 从源分层单独输出**完整底托**；若只有模拟裁图不保真，待修复 |
| KPI各类纯色圆盘背景 | `css` | CSS圆形渐变容易且无分层收益 | 不切`deco_kpi_*_disc.png` |
| 中央立体中国地图、独特发光纹理 | `component` | 高保真结构复杂，CSS不易等价实现 | 优先源层独立导出；需完整透明边 |
| 多层立体地图舞台、环形真实反射 | `component` | 有不可替代的几何与材质层次 | 优先源层完整导出，严禁“只剩上半圈” |
| 大屏整体纯黑/简单线性暗渐变 | `css` | 无需PNG，不增加价值 | 不额外导出 `bg_dashboard.png` |
| 不可通过CSS忠实重现的唯一大背景纹理 | `background` | 确有真实图像/纹理信息 | **只此时**导出完整背景PNG；不许截一半、纯黑或虚构遮挡像素 |
| 整张大屏效果图 | `preview` | 是验收基线，不是HTML背景 | 独立保存，不允许作为唯一图层 |

复合组件（比如“前景图标＋3D底托”）可在HTML叠加；若确需额外交复合版，应标 `component`，但独立的 `icon` 仍然必须可复用。**不为凑文件数量重复切完全相同的背景/底托。** 认可图细节优先；不能仅因为CSS方便就将复杂3D底座降级为平面渐变。

## 三、背景重建的真实边界

- 用户只要求PNG图标并允许HTML重建，不意味着必须交一张“纯黑整页背景PNG”。背景只要用HTML/CSS**忠实还原**即可；如果用户明确指定PNG背景，按其要求提供完整、非空、真实可用的背景图。
- **背景是层，不是画面某块矩形截图**。不能拿遮挡过的扁平截图“抹掉前景”后当做真正原背景；原图被挡住的像素不可逆恢复。
- **不可凭空做黑底来掩盖欠缺的原图纹理**。当前素材 `stage_3d_plinth_masked.png`、`deco_header_chrome.png` 等只从文件夹图能看到疑似不完整/深黑问题，须从原层核验；来源只有扁平图时，重建后在同一视口与认可图对照，不合格不能进入最终ZIP。
- 导出整页背景时必须具有原画布宽高、完整解码与预期透明度。**真正的整页背景默认全幅不透明**；只在局部有透明叠加的素材，应归入`component`而非伪装整页背景。纯色和几何背景优先CSS。

## 四、边缘质量（E0～E5；所有需要PNG的元素逐件检查）

| 关口 | 操作 | 失败判据 |
| --- | --- | --- |
| **E0** 源层完整 | 确认原图层/原高分辨率图，圈定**完整主体与投影/发光延伸**，先看源分辨率 | 从聊天缩略图反复放大；图像仅剩半块 |
| **E1** 独立遮罩 | 保留主体、光影与有效透明羽化；优先原透明层/vector/渲染Alpha，位图抠图需精修mask | “相近黑色一键透明”抹掉底座与阴影，留下黑边 |
| **E2** 抗锯齿与色彩 | 以线性/正确色彩空间处理Alpha边缘，检查预乘与直通Alpha转换；**透明边缘RGB不保留脏黑白底** | 彩边、锯齿、灰白/黑色光晕残留 |
| **E3** 无内容裁断 | alpha有效图层包围框完整，检查上下左右各边触图情况；需要贴边扩展的素材需显式记录 `intentional_bleed` | 亮边突然被齐切、地图缺角、底座缺半圈 |
| **E4** 实际显示复核 | 100%画布与200%/400%局部放大检查；叠在透明棋盘/浅/深底；HTML实际缩放比对 | PNG单看似正常，但放在页面出现白边毛刺、糊和断层 |
| **E5** 金样与交付 | 实际HTML浏览器渲染同画布分区比对，签收高关注图标、底座、地图、背景，重新生成ZIP | 使用错误图片做金样、缺浏览器截图、差异未修复 |

注意：**“Alpha边缘有中间值”不自动证明没有毛边；“Alpha边缘非常锐利”也不自动证明有错**（几何直角有时需要硬边）。数值工具可以发现“触边裁断”“大面积空白/透明”“几乎纯色背景”，但**不能凭单一阈值认定高质量抗锯齿**，必须按金样人工核对。

## 五、交付清单要记录“为什么切它”，不是只记录“切了几张”

将资产清单升级为 `schema_version: "1.1"` 时，额外填写：

```json
{
  "schema_version": "1.1",
  "canvas": {"width": 1920, "height": 1080},
  "background_strategy": "css",
  "entry_html": "index.html",
  "css": ["css/style.css"],
  "js": ["js/app.js"],
  "preview": "preview/full-page.png",
  "assets": [
    {
      "id": "icon-logistics",
      "role": "icon",
      "path": "assets/icons/icon_business_logistics.png",
      "source_kind": "layer_export",
      "reason_png": "independent glowing freight symbol"
    },
    {
      "id": "map-3d",
      "role": "component",
      "path": "assets/components/map_3d.png",
      "source_kind": "layer_export",
      "reason_png": "intricate relief, routes and emissive edges",
      "edge_policy": "closed"
    }
  ],
  "required_text": ["业务运营可视化平台"],
  "required_interactions": ["navigation"]
}
```

- `background_strategy` = `css` 或 `image`。**css时背景不要求PNG，且不能提交无必要的`background`素材；image时必须有确需图像的完整背景PNG**（显式要求PNG背景时只能选image）。
- `source_kind` = `layer_export`、`masked`、`reconstructed`。**`masked`背景不能直接当合格整页背景**，须从可编辑源文件导出或重建并有人工验收证据；任何标注不能代替实际文件。
- `reason_png` 是独立资源必要性的理由，不能写“因为需要切图”或“因为原图有它”；若纯色/单层圆盘/导航标签应改用CSS/HTML。
- `edge_policy` = `closed`（组件完整，没有可见内容触碰裁切边界）或 `intentional_bleed`（用户认可的真实边缘贴边并留有完整复合关系）。**不能在测试失败后随意改成intentional_bleed。**
- `assets` 里列真实存在且HTML/CSS/JS引用的必要资源；不要求至少有一个背景PNG。用户特定要求始终优先，且无权通过删改manifest把用户要求从交付标准中消除。

## 六、实用检查与未验证限制

当一个组件从PSD拆为多张PNG后，**视觉单元是否完整必须单独验收**：一个`plinth`不等于完整`glyph＋plinth`业务图标；用户要完整图标时必须交复合PNG/或组合预览及真实HTML。实际源分辨率不足不能通过插值修复，执行[Photoshop级源层精修SKILL](../skills/photoshop-grade-asset-extraction/SKILL.md)与`scripts/audit_cutout_source_quality.py`检查原生像素、目标DPR、层叠配对、完整合成预览。这些依旧不能自动保证无毛边，必须回源图层处理。

1. 在真实资源目录执行 `python scripts/verify_ui_delivery.py delivery/ --zip delivery.zip`；它对1.1清单检查角色与资源、背景策略、PNG大小与透明度、组件裁断风险、必要性说明，并与原有HTML/ZIP测试兼容。
2. 运行 `python scripts/audit_asset_edges.py delivery/asset-manifest.json --root delivery --contact-sheet working/asset-edges.png`，生成组件边界、Alpha和可疑空白/纯色背景诊断及三底色预览（不会修改原PNG），用金样逐件复核。
3. **脚本PASS只说明它能检测的硬约束通过**；不会知道中国地图哪个省缺边、3D平台哪个透视缺失、边缘是否完全美观。真正高保真仍依赖原件、分层源图、同画布真实HTML与用户验收。

**最新专项纠错**：底部3D底托的黑色侧壁可能是**合法实体内容**，不能为去毛边一键删黑；真正黑底污染应从可编辑几何、独立真Alpha重导。自动Alpha紧裁适用于独立symbol，不适用于需要保留`layer_anchor`的辉光/底托。实际CSS/HTML同坐标合成结果需按[HG0～HG6与ROI验证工具](VISUAL_UNIT_GLOW_REGRESSION.md)检查倾角、缺半层、光效裁断，不能仅凭PNG边框/静态RGB均值通过。
