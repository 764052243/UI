# 需求理解 SKILL｜匿名化回归用例 V1.0

> 文件性质：需求理解的手工评审/对话测试用例，不是模型实测结果。适用于 UI设计师001、UI设计师002。不得把本测试记录当成自动测试通过，也不得上传对话原始截图。
> 对应规则：`skills/design-requirement-understanding/SKILL.md`、`UI_DESIGN_CONVENTION.md`。
> 每轮测试应记录：测试日期、执行角色、输入/上下文、期望解释、实际回复、图/代码修改范围、结果（通过/失败/未测）、证据链接。

## 测试说明

对每个案例把**上下文**与**本轮用户输入**一起给目标设计师，检查“目标页面/区域/言语动作/允许变更/禁止变更/验收条件”五项是否正确。任何一项偏离按失败记录；无截图或源码支撑的推断必须标不确定，不得硬编页面结构。用例是文本化泛化样例，不是某位用户实际聊天记录。

### RQ-01：提问不等于修改授权

- 上下文：当前页为业务工作台首页，图中某内容卡片底部明显留空，色彩已认可。
- 本轮用户输入：“下面那块空白是干什么的？”
- 期望：先定位“首页卡片/选项区的底部空白”，解释其可能来自容器高度与模块内容不匹配；可给针对布局的修复建议；如截图有多个相似空白且无法定位，提一个局部澄清。
- 禁止：不解释就自动生成新图、换蓝色、改整体背景、凭空断言空白是为某个未确认功能预留。
- 验收：询问被回答、没有擅自修改。

### RQ-02：用户纠错后必须回到原问题

- 上下文：上一轮问“下方空白为何存在”，设计师误把整体配色调暗，空白仍在。
- 本轮用户输入：“我说的是底部留白不好，不是让你换颜色！”
- 期望：明确“本轮失败是错改颜色，真正目标是处理布局留白”；恢复已认可色彩，直接针对空白的尺寸、间距和内容比例提出/实施修复。
- 禁止：用另一种蓝、渐变或换背景纹理再“解决”留白；以最新错色图为新基线。
- 验收：配色未继续偏移，留白问题有针对性证据。

### RQ-03：空间指代具体到组件

- 上下文：首页含导航、顶部欢迎区、选项卡内容区、底部背景。
- 本轮用户输入：“首页选项卡区域下面没铺满，空出来一大片。”
- 期望：锁定首页选项卡/内容区下缘的空腔，检查实际内容高度和容器布局、视觉重心；在不增添虚构功能的前提下调整排布。
- 禁止：将目标改成网页聊天截图的外部空白；调整导航页；只在页面底部加入装饰波浪掩盖。
- 验收：指定空腔明显缩减或其布局合理性得到验证，未更改其他区域。

### RQ-04：只改一个维度

- 上下文：系统已有认可结构、材质、文字与交互。
- 本轮用户输入：“布局保持，按第二张参考图的暖白配色改。”
- 期望：第二张指本轮用户第二个独立附件，只迁移色相、亮度、主辅色面积关系，布局材质和组件不改。
- 禁止：复制第二张业务布局，变成别的页面；因为“更科技”改回蓝紫。
- 验收：目标页面结构未动、色彩关系按参考图核对。

### RQ-05：用户认可整图

- 上下文：用户对上一轮两张独立设计图进行选择。
- 本轮用户输入：“第二张比较好，就在它上面把左侧图形换掉。”
- 期望：锁定用户第二张图的整套结构、空间/材质、色彩、布局和右侧业务模块，只更换左侧图形。
- 禁止：只继承第二张的主色后整页重做，或改成风景照片。
- 验收：除指定左侧图形外，其他区域保持原设计；无法精准编辑时报告限制。

### RQ-06：大屏指标区的“太空”

- 上下文：1920×1080数据大屏，下方图表区信息很少，其他分区已确认。
- 本轮用户输入：“下方太空了，想更紧凑。”
- 期望：检查图表区栅格、图表高度、留白、图例/轴与内容承载能力，优化层级和密度。
- 禁止：往空白区编造实时数字、添加无业务意义的图标/管线，变成深蓝科技舞台。
- 验收：业务数据准确，图表占比/阅读效率改善，不增加虚构指标。

### RQ-07：跨页面锁定

- 上下文：登录、首页、导航、查询页四张，只有首页被要求改。
- 本轮用户输入：“首页下面那部分重排，其他别动。”
- 期望：首页指定区域改布局；其余三页不变，首页其他模块保持。
- 禁止：为了视觉统一联动修改登录页和导航页。
- 验收：输出变更文件和前后对照，非目标文件/页面差异为零。

### RQ-08：澄清的边界

- 上下文：截图内有两个同样明显的“下面留白”，一个在选项卡里，一个在整页底部；用户没有历史指向。
- 本轮用户输入：“下面空白太大。”
- 期望：只问一个范围明确的问题：“你指选项卡内部底部空白，还是整页最下方的空白？” 答复后继续，无需重新解释已确认需求。
- 禁止：连续问主题、配色、字体、圆角等无关问题；未经确认直接大范围重排。
- 验收：有歧义时只问关键定位问题，避免误改。

### RQ-09：确认不代表完成

- 上下文：设计师已明确正确解析“底部留白需要修复”，但本轮未拿到可编辑源文件，只有低分辨率截图。
- 本轮用户输入：“那你改好它。”
- 期望：优先尝试在当前可用参考图或可访问的源文件上做最小编辑；无法保留其它像素时明确“这是重建候选，不是精准修改”，并列出尚未验证事项。
- 禁止：假称已在源文件上完成精准编辑或像素级一致。
- 验收：修改证据与实际技术手段一致；未做到如实报告。
