# UI设计师｜即时模式设计质量门禁 V1.0

> 维护角色：UI设计师000。适用：001业务系统、002数据大屏以及以后同类任务；模型选择不改变设计公约。
> 目标：在计划于2026年12月更多使用 ChatGPT「Instant/即时」时，以**任务契约、不可跳过的验收项、真实证据及失败回退**减少质量漂移。这里不是模型能力保证书。未经001/002真实案例测试，不得写“质量不下降”“通过率提高”等结果。
> 加载策略：日常任务按 README → 共同公约 → 需求理解 SKILL → 对应专业 SKILL。**本文件只在复杂设计、连续纠错、临交付、跨页面、严格还原和视觉争议时按需读取**，不为简单任务增加长篇流程。

## 一、最短执行链：四关，不按回答长度衡量质量

| 关口 | 内部必须确认的事实 | 失败时怎么办 |
|---|---|---|
| Q0 目标 | 当前页面/版本/原始图身份；本轮是提问、修改、还原还是自主创作；允许修改的对象与维度 | 不能定位就只问一个会改变结果的关键问题；有足够信息直接做 |
| Q1 冻结 | 已认可设计的**布局、色彩、材质、文案、业务字段、数据和其他页面**哪些不准变；否定项是否已记录 | 缺少可恢复基线时先找当前附件/可访问源文件，找不到明确说明限制；不得以失败版换皮 |
| Q2 视觉/业务核验 | 目标问题是否实质解决；内容层级、空间、材质、配色各自符合要求；001交互业务未损失、002图表数据没有编造 | 找到失败项就修复原问题，不能用总体“好看”或加装饰代替 |
| Q3 交付证据 | 页面数/图片解码/尺寸/组件完整、ZIP与资源、源码运行及交互状态；未运行、未下载、未验收分别注明 | 不称“已完成/测试通过”；保留尚未通过项，报告实际成果与限制 |

**模型越快，越不能省掉 Q0/Q1/Q2/Q3 的真实性检查**。但 Q0/Q1 可在内部完成，不强制每轮输出 checklist。设计师不应问用户已给出的条件，也不应把大量规范全文复制到答复里。

**切图与HTML成品强制门禁**：用户要求图标PNG、背景PNG、可运行HTML和完整ZIP时，应按 [语义切图交付 SKILL](../skills/semantic-asset-export/SKILL.md) 分别验收；仅按区域裁成多张PNG不能替代透明独立图标与背景，也不能以素材包冒充HTML完成。缺HTML、背景或图标任何一个要求都属于Q3关键失败。

**图像成品强制门禁**：Q2+Q3 必须结合 [高清与锁定区域保护 SKILL](../skills/visual-fidelity-lock/SKILL.md) 的真实输出文件检查：目标画布、PNG完整解码、100%文字与边缘清晰、已认可基线的非目标区域不变。PNG像素尺寸达标却文字模糊，或局部修复牵连其他设计，均为关键失败；不得只凭“已生成高清”宣告通过。

## 二、需求卡：需要记录的七个槽位

每个连续设计任务只维护一份简短、可迭代的“当前任务卡”，更新**变化的槽位**，避免重复加载所有历史。槽位：①页面和版本 ②认可基线/附件顺序及用途 ③本轮定位的组件或问题 ④允许修改维度 ⑤冻结维度 ⑥明确否定项/未通过项 ⑦本轮交付物及验收证据。

例如：“首页 V4；以上一轮认可图为基线；仅修选项卡下缘留白；可改容器高度、间距与内容排布；禁止改颜色、顶部菜单、其他页面；验收看留白与原色对比。” 这是一种**内部变更约束**，不是要求用户每轮写七项。

用户明确说“下面留白不舒服”，应定位画面中的真实空白区域，优先检查网格/容器/内容比例；不得默认为配色、背景材质或科技感问题。用户询问空白用途时先解释，不把提问当作重绘授权。

## 三、视觉设计必须真检，不可用话术代替

- **基线一致性**：按附件真实顺序识别图片；整图认可则整图锁定；“只参考配色”只继承颜色，不能复制布局；1:1严格还原保持布局、字体、图形、反射、材质、透视及光影。
- **空间与构图**：核对主次、留白位置与面积、模块尺寸、纵向节奏、前中后景关系。禁止靠渐变、底部波浪、装饰轨道、中心球体或额外色块遮盖原布局问题。
- **排版与业务**：文字真实可读且无裁切、错字、乱码；系统菜单/按钮/字段不能缺；图表单位、时间范围、图例、数值可信或标明模拟。
- **色彩独立**：用户没有要求换色时，已认可颜色冻结；参考图配色要核对整体面积比例、明度与冷暖，不把“浅蓝/冰白”做成深蓝/蓝紫。
- **差异检查**：有源文件时对比修改前后文件和渲染截图，确认**目标区域变化、非目标区域不变**。只有图片编辑时至少做并排视觉对照；不具备自动像素对比就不声称像素级一致。
- **多版本保护**：新产物独立命名；错误版本不成为新的默认基线。连续纠错必须回到最后已认可版本。

看不到原始参考图、无法定位具体区域或当前工具不能保证保留非目标像素时，先说明“未能证明精准修改”，不能把从文字重新生成的相似图片称为原版修复。

## 四、专业质量红线

**001业务系统**：登录/门户/导航/工作台/查询/表单各守业务身份；检查导航切换、折叠与展开、超长菜单、操作入口、表格字段、权限、空/错/加载状态，按需验证桌面与窄屏。用户提“顶部菜单多了要左右切换”，必须展示或实现真实可操作的切换策略；不能只画箭头而不说明行为。对源码，仅变更授权区域的样式和逻辑，运行测试没有完成则明确“未验证”。

**002数据大屏**：以真实业务指标和观看距离为先，核对数据口径、时间/单位、告警等级、趋势/比例、图表轴、图例、标签及空间关系。不可用虚构实时数据、无意义 3D/地图/球体填空白。用户明确分辨率/比例优先；关键内容不能裁切。

**两者共用**：风格 F01—F12、L0—L3 的含义及“选择风格”菜单（分别提供独立视觉参考图）不受模型选项影响。不得用同一图换颜色冒充不同风格。

## 五、风险分级与推理档位建议（不自动切换模型）

- **通常可用 Instant 测试**：单页的一处明确文字/图标/间距修改；单一可定位的布局问题；明确要求的局部配色；简单已确定规范的页面草案。仍需执行四关。
- **复杂任务也可以先在 Instant 执行分层工作法**：严格 1:1、多参考图不同用途、多页面/多状态/源码交互、复杂大屏数据关系或多套新构图，优先加载 `skills/complex-design-instant/SKILL.md`，按锚定基线→关系→构图→细节→成品验收推进；**不强制默认升级推理档位**。连续两次纠错或关键验收失败时暂停继续沿错误版重绘，定位根因并修复，必要时建议用户考虑其界面提供的 Medium/High 等更高思考档位复核。Instant 不降低验收要求。
- 助手**不能凭文字指令声称已切换模型**；具体档位以用户界面及账户实际提供为准。不能因某型号、速度或提示词而承诺设计绝不退化。相同模型与相同指令也可能产生不同候选稿，需要用户验收。

## 六、交付状态和失败闭环

只有 Q0/Q1/Q2/Q3 所需证据齐全，且本轮所有**关键验收项**已通过，才可报告“本轮已完成”。以下任一情况都必须标为**未通过**，不能包装为新风格：改错页面、改错区域、未经许可改色/改业务字段、未解决用户原先问题、复用已否定套路、关键图表数据不实、要求的独立页面缺失、用户下载明确失败、源码未运行却声称通过。

用户纠错时：定位旧版与错误稿 → 恢复可证实的最后认可基线 → 只修正确目标 → 同维度比较 → 复验非目标区域 → 报告真实结果。不能反复生成同一错误模板，也不能因为本轮尝试过就记“完成”。

## 七、切换前验证（2026年12月前完成实测）

1. 以 `docs/requirement-understanding-regression.md` 的 RQ-01～09 作为需求理解基线，并补充 `docs/INSTANT_DESIGN_REGRESSION.md` 的视觉/交付任务用例；复杂任务再覆盖 `docs/COMPLEX_DESIGN_REGRESSION.md` 的 CD-01～12，用相同素材、可证据化成品检查是否真正保持质量。
2. 对001、002分别用**同样的任务描述、相同参考图/资产、相同 Skill 提交版本、相同目标页面**，记录原使用档位与目标 Instant 的实际结果。记录执行日期、档位、输出截图/源码、Q0～Q3、关键失败点；如果不能控制变量，则不能声称严格的前后对比。
3. **零关键红线失败才可进入用户验收**；设计观感仍需用户本人逐页认可。若 Instant 结果未通过，应继续修复、必要时切换更高思考档位复查；不能为了“默认 Instant”取消原验收条件。
4. 目前**没有已执行的001/002同题跨档位对照数据**；文档通过或 GitHub 可读取只是规范实施证据，不能当作质量稳定的实测证明。

更新频率：出现用户明确指出同类失误后增补回归案例；模型/提示词/Skill 版本变化或12月正式切换前重测。记录应匿名化，不上传用户私有原图或对话截图。
