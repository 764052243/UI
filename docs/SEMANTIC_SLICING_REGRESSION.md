# UI设计师｜语义切图、独立PNG与HTML交付回归 V1.0

> 适用：001业务系统、002数据大屏。**案例定义不等于已经通过实际设计测试**；真实用户图像和聊天截图未经归档授权不得上传 GitHub。只有真实完成图片、HTML和ZIP，逐项核验后才能报告某案例通过。
> 失败背景：已确认大屏截图被按25个矩形区域切成多个带菜单文字/背景的PNG，缺独立透明图标、可铺设背景与HTML；这种状态为 **S1背景/S2图标/S3 HTML/S5完整交付不通过**。

| 用例 | 实际用户要求 | 正确交付与验收 |
|---|---|---|
| SL-01 | 从整张大屏提取“导航图标” | 每个图标独立透明RGBA PNG，排除完整文字/底色横条；逐一核对透明边、光晕、可用尺寸；图标并非所有导航按钮截图 |
| SL-02 | 输出一个完整大屏背景PNG | 整页原画布尺寸背景，无标题、指标、菜单、前景地图及按钮文字；不能把原完整视觉稿当背景 |
| SL-03 | 背景被原图上的卡片/图标遮挡 | 优先取得源文件；若从扁平图无法无损提取，记录“需要补绘/重建”并如实说明；不虚构已恢复隐藏底图 |
| SL-04 | 不同状态导航按钮的图标PNG | 图标普通/激活/禁用状态独立交付或按本轮要求；每张无周边组件背景与文字，不漏状态 |
| SL-05 | 用户要求“切图+HTML” | 除PNG资产外交 `index.html`、`css/style.css`、`js/app.js`；真实DOM文本/图标引用；不得只交“25张PNG打包” |
| SL-06 | 将整屏截图塞入HTML的img或CSS背景 | 判失败；必须使用语义DOM/布局/资源，在代码中引用独立图标和背景；真实指标/按钮不应全部被烘焙在一张图 |
| SL-07 | 资源目录完整但 HTML 没引用图标/背景 | 判失败；实际引用清单中的各项资源，静态路径合法且不404；可用 `scripts/verify_ui_delivery.py` 辅助检测 |
| SL-08 | 切图PNG为RGB且带黑白矩形底 | 判失败；独立图标应真正支持Alpha透明、避免白边黑底和裁断发光；人工核对底色脏边 |
| SL-09 | HTML存在但菜单/切换不可操作 | 静态文件通过不代表交互通过；启动浏览器实测导航切换/状态反馈，未实现则单独标未通过/未测试 |
| SL-10 | 要求ZIP但只有PNG、没有HTML或manifest | 文件数与目录契约不符；ZIP需完整且可解压，包含HTML/CSS/JS/背景/图标/预览/asset-manifest；必须实际逐项校验 |
| SL-11 | 只要求截图分割成多个矩形区域，不要求语义资产 | 可以按用户明确范围裁分块；不擅自新增HTML，也不把纯区域分块命名为独立图标/背景 |
| SL-12 | 多次纠错，之前切图混入大片背景 | 回到已认可源图，重新提取独立图标与干净背景，保持原设计不变；失败矩形块不成为新版基线 |

## 自动检查与真实验收的区别

- **自动检查**：运行 `python scripts/verify_ui_delivery.py delivery/ --zip delivery.zip`，报告清单、路径、PNG解码与 alpha、背景尺寸、HTML文本和资源引用、ZIP完整性；按 JSON 的 `status` 记录真实结果。
- **真实视觉检查**：人工查看每个透明图标是否去除了菜单底图和文字、光晕是否裁切、背景是否剔除了前景模块；自动脚本**不能**准确理解原图层的视觉内容。
- **实际浏览器检查**：打开 `index.html` 检查CSS/JS/图片加载、菜单/按钮实际操作、指定画布下显示；不应宣称代码存在等于已运行。
- **用户认可**：只有用户核对产物并认可后才能称其为已确认基线。用户下载状态不可由仓库工具推断。
