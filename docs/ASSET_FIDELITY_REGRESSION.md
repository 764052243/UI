# UI设计师｜语义切图视觉一致性专项验收 V1.0

> 状态：**规范及测试计划**；现有示例为用户反馈场景，**尚未使用002的可编辑原始大屏、资源包、实际HTML渲染在相同视口开展对比**。此文不上传用户原图、失败截图或重绘件。
> 基线：用户本轮提供两张对照图，明确**第二张是效果金样，第一张是切图/组装版的未通过结果**。第二张的整体构图、模块比例、图标样式、材质光效、地图体积、立体底座、排版/文本关系均是要还原的对象，不能缩窄为“颜色参考”。

## 1. 当前可以从对照图识别的失真风险

观察两图的相同业务结构后，当前重点需要按原始PNG/实际HTML精准核查，而非把图标全部“重绘成差不多”：

| 高关注区域 | 需验证的差异 | 失败判据 |
|---|---|---|
| 顶部品牌标题与导航 | 顶栏高度、装饰切角、激活橙色按钮厚度、图标轮廓与文字对齐、间距和高光 | 导航比例/光效/图标样式与金样不一致；裁块含周围底色 |
| 左侧运行态势、趋势、结构 | 面板边框材质、内边距、数值字号、图表线宽、图例、圆环/阴影 | 图表形状和数字错位、框线变形、文字模糊 |
| 顶部四项指标卡 | 图标的真实体积、颜色、投影、图文比例、卡片高度和间距 | 图标替换成平面符号、贴边/裁光、卡片失真 |
| 中央地图与平台 | 中国地图立体厚度、橙蓝边缘、发光节点/连线、透视；**多层底座的环形结构、反射和光源** | 地图变形/层级塌陷、底座简化为平薄圆环、阴影/高光消失 |
| 右侧告警、排名、动态 | 图表/圆环、行距、边界、按钮和告警色一致性 | 圆环比例、列表排版和内容错位，局部内容被背景吃掉 |
| 底部重点业务运行 | 五个**具有自身形体、厚度、投影、底托**的图标/卡片，状态条与数字排版 | 将底座和立体图标换成扁平线稿、裁切光晕或文字覆盖 |

以上为**验收焦点，不是假称已经进行像素测量**。仅依赖聊天缩略图无法可靠给出每个图层的精准坐标/差异百分比；需要002取得原始文件、切图目录和真实 HTML 渲染截图后验证。

## 2. F0～F5 视觉回归操作

1. **基准声明 F0**：用户认可版本明确标注 `reference_id`、图像尺寸、来源文件 SHA（可在私有交付目录登记）、字体和渲染环境，禁止使用第一张失败版作基线。
2. **来源溯源 F1**：每个资产记录 `extracted | masked | reconstructed`，包含源图层/原图坐标与用途。重建项须单独说明哪些遮挡细节不可恢复；不得把重建图假报无损原图层导出。
3. **逐图符号检查 F2**：导航8个图标、底部5个业务图标及其他实际需求的资源逐一检查：Alpha透明、物体轮廓、尺寸、中心、线宽、厚度、透明渐变、发光、阴影、颜色、暗亮背景中的边缘表现。缺1个就不能靠其他图标通过抵消。
4. **HTML几何定位 F3**：配置相同画布/浏览器缩放/DPR/字体/固定数据/动画帧，记录每个关键DOM的 bounding box，比较 CSS 渲染位置、宽高、层级和溢出；不能靠整体 `transform: scale()` 压扁主体解决定位。
5. **浏览器金样比对 F4**：在同视口截取真实 `html-render.png`，与第二张金样用`scripts/verify_visual_reconstruction.py`逐区比较；全页和每个关键 ROI 都必须满足**事先确定**的阈值，同时人工检查图形材质和文本。不同画布不得先把其中一张拉伸成另一张冒充同尺度还原；先在源文件真实同画布重导。
6. **F5 缺陷闭环**：修复顺序：①错误图源/遮挡层 → ②几何布局 → ③图标形体和贴图 → ④地图/底座材质与光影 → ⑤文字图表 → ⑥边缘透明 → ⑦交互与ZIP。修正后整个页面仍须复验；不能放宽阈值/缩小ROI/删除失败项来制造通过。

## 3. 视觉对比脚本与配置

`scripts/verify_visual_reconstruction.py` 是**图像差异诊断器**，依赖 Pillow，仅接受**同真实画布**的参考 PNG 和浏览器截图，不自动缩放/对齐以掩盖失真。它在整体及每个关键ROI计算「超出容差的变化像素占比」「RGB绝对差均值」及仅供定位的边缘差异，并给出分区域失败结果。**自动通过不等于图片抠图干净、图标高保真、文字正确或业务交互已通过**。

每个用户项目在**制作候选截图前**根据经确认的参考图尺寸建立独立 `fidelity-plan.json` 并固定阈值。下面只给一个**合成40×30测试图**的配置格式，不是该大屏真实坐标或通用推荐阈值：

```json
{
  "schema_version": "1.0",
  "reference_id": "approved-v1",
  "whole_canvas": {
    "max_changed_fraction": 0.10,
    "max_mean_rgb_difference": 8,
    "pixel_tolerance": 0
  },
  "regions": [
    {
      "id": "navigation",
      "box": [0, 0, 40, 10],
      "thresholds": {
        "max_changed_fraction": 0.01,
        "max_mean_rgb_difference": 2,
        "pixel_tolerance": 0
      }
    },
    {
      "id": "map_stage",
      "box": [0, 10, 40, 30],
      "thresholds": {
        "max_changed_fraction": 0.20,
        "max_mean_rgb_difference": 12,
        "pixel_tolerance": 0
      }
    }
  ]
}
```

真实大屏计划至少单独覆盖：顶部品牌/导航、顶部指标、左三面板、中央地图/底座、右三面板、底部五业务单元；尽量为关键图标建立更小ROI，避免大背景稀释图标错漏。所有阈值**事先锁定并保留审查证据**，不能因为测试失败再人为改松；有大量动态内容的区域先用测试数据/时间冻结，不能将它们简单从检查范围删除。

```bash
python -m pip install Pillow
python scripts/verify_visual_reconstruction.py \
  --reference preview/accepted-reference.png \
  --actual preview/html-render.png \
  --plan fidelity-plan.json \
  --report reports/fidelity-report.json

python -m unittest discover -s tests -p 'test_verify_visual_reconstruction.py' -v
```

脚本退出码：0＝全页/ROI定义阈值内、1＝至少一项未通过、2＝配置/图片读取错误。无原始金样、无同尺寸浏览器截图、无检查计划时**F4不算通过**。

## 4. 本次新增 RV 回归案例

| 案例 | 场景 | 关键验收 |
|---|---|---|
| RV-01 | 透明PNG有Alpha，但导航图标带黑边/白晕 | 暗底亮底都无脏边，轮廓和原图线宽一致 |
| RV-02 | 立体图标被换成扁平图标库图形 | 保留原体块、厚度、投影及独立底托 |
| RV-03 | 地图从合成截图扣取后边缘粗糙 | 地图完整、无错色/遮挡残影、节点线及光影不缺 |
| RV-04 | 底座被简化成单一扁平椭圆 | 保留金样层次、透视、橙色外圈、反射与结构 |
| RV-05 | CSS布局总体像但顶部导航高度/间距不同 | 同视口定位和层级，分区对比不能只看总体 |
| RV-06 | 整体差异阈值通过，某个图标严重失真 | 关键小ROI失败必须整体失败，不能全页均值遮盖 |
| RV-07 | 截图被整体拉伸来匹配金样尺寸 | 画布不同时拒绝比较，不允许自动缩放冒充还原 |
| RV-08 | 背景去前景时出现模糊补洞、黑块 | 源图层提取优先；无源文件重建记录不确定范围并人工验收 |
| RV-09 | 地图/卡片玻璃与发光效果丢失 | 实际渲染并排复核光源、羽化、阴影与层次 |
| RV-10 | 图标和菜单PNG重复烘焙文字，HTML又叠一次 | 原图标不含文字，DOM只保留一份文本，无重影/错位 |
| RV-11 | 修复某个图标造成其他模块改变 | 从认可基线出发，非目标页面/区域按锁定保护比对 |
| RV-12 | 只有资产PNG没有真实浏览器截图 | S0～S3可能部分通过，但F4/S4未验证，不能报高保真完成 |
