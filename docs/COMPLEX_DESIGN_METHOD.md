# UI设计师｜复杂设计分层方法论 V1.0（Instant 优先）

本方法论与 `skills/complex-design-instant/SKILL.md` 配套，供001/002在复杂页面、多参考图、高保真与复杂交互任务按需读取。**Instant 是用户选择的模型工作模式，不是必须降低精度的设计方法。**方法论旨在使关键决策可追溯、错误可定位、结果可复验；没有实际跨档位对照数据就不能承诺视觉质量必然不下滑。

## 1. 原则：把复杂性从一次性“大生成”转成可检查的“状态+约束+产物”

容易失误的模式：同时理解多张图、业务、色彩、布局、材质、交互后立刻出最终稿；随后用户说“底部空白不协调”，设计师误改配色，并把错稿当成下一版基线。

采用 **ANCHOR → MAP → LAYOUT → VISUAL → VERIFY（AMLVV）** 五步：

| 步骤 | 产物/检查对象 | 不可跳过的决定 |
|---|---|---|
| ANCHOR 基线锚定 | 用户任务卡、图片真实编号、版本与锁定清单 | 是还原、局部修改还是自主创作？哪些绝对不能动？ |
| MAP 关系建模 | 页面图/模块关系、数据语义图、必要交互状态表 | 系统如何被使用？数据/页面如何关联？没有数据来源不把假设当事实 |
| LAYOUT 构图骨架 | 区域比例、内容密度、阅读顺序、组件占用 | 版式本身能否解决业务问题？是否仅靠装饰补空白？ |
| VISUAL 视觉深化 | 颜色/材质/空间/字体/图标的分离核对；必要源文件 | 已认可维度是否未变？视觉是否真正符合指定参考？ |
| VERIFY 成品核验 | 实际图片/渲染图/交互/代码/ZIP/差异证据 | 关键条件逐项通过了吗？未测试的是否清楚标明？ |

步骤是**内部执行序列，不强制五轮对话**。单轮可完成就一次性完成；不必请用户逐一审批。当前任务需要人工判断但上下文已明确时由设计师决定。严格1:1还原不能用 MAP/LAYOUT 自行创造新结构，只能识别原有结构并还原。

## 2. 任务拆分的具体规则

### 2.1 约束优先级和冲突处理

使用“权威来源 → 作用范围 → 变更许可”的三元组：

- 用户本轮明确指定的“配色仅参考图1、布局参考图2、登录表单锁定”分别作用于颜色、结构、表单；不能混作一张风格图。
- 用户明确认可整张图，则整张为主视觉基线；后来的局部修改命令只开放相应区域。失败生成图不自动成为新基线。
- 未明确的美术细节可主动决定；未明确的业务内容不能编造成已存在的字段/指标/真实数据。
- 若同一维度有真实冲突，优先按用户**本轮更具体更新**的指令处理；若仍存在两种明显不同结果，只问一个确定性问题。
- 避免基于“更现代”“更科技”擅自覆盖颜色、材质、业务逻辑、页面范围。

### 2.2 页面/参考图矩阵（内部维护）

| 页面 | 输入参考与用途 | 已锁定 | 允许改变 | 本页验收 |
|---|---|---|---|---|
| 首页 | 图A：整图认可基线 | 配色、菜单、卡片材质、其余区域 | 选项卡下方排布/高度/间距 | 空白改善，原颜色和其他区域保持 |
| 登录页 | 图B：配色，图C：结构 | 右侧表单、参考图结构 | 左侧非风景背景图形 | 对应两图作用范围正确 |
| 数据总览 | 1920×1080、指标数据 | 数据口径与告警语义 | 指标比例、图表布局 | 大屏数据可读且准确 |

这是**格式示例**，不是默认向真实任务添加页面或数据。用户若只要求首页则不凭空扩展登录/大屏。

### 2.3 多约束的分解策略

- **内容固定，视觉自由**：先锁定字段、操作、指标与业务关系，再设计构图；不因视觉效果删菜单/筛选。
- **视觉固定，局部可改**：先找到认可的源图/代码，复制为新版本，处理指定选区；非目标区域保留，不拿文字重生成的图冒充原图编辑。
- **视觉/业务均有待设计部分**：先做信息架构和文字层级，避免一开始把装饰当业务结构；然后推进细节。
- **系统+大屏混合**：共享品牌 token，但各页的交互、构图、信息密度按专业 SKILL 分别解决，不用“大屏模板”替代业务列表页。

## 3. 阶段产物选择：用最便宜的有效证据拦截错误

- 信息架构不清时：先写极简页面关系/组件状态表，不先生成高成本高清视觉稿。
- 布局问题时：先核对容器高度、区域比例、网格与内容体量；已有代码就查 DOM/样式，**不先换背景颜色**。
- 构图需要两种方向时：比较实质不同的区域关系/视觉层次，不把同一骨架涂两种颜色当新方案。若用户明确“选择风格”，先按独立 F01—F12 参考图规则展示，不越过选择关口。
- 材质/高保真问题时：检查玻璃反射、光源方向、厚度、体块和背景关系；“浅蓝”不是“纯平面”，不能因即时出图而降级空间层次。
- 必须交付源代码时：先选定已认可视觉基线，按该视觉实现实际可运行组件；检查交互、资源引用、不同屏宽与状态，不把设计 PNG 当可交互系统。

不要为了节省调用跳过必要图像检查、文件检查或真实运行。没有工具能够证明的项目只写“未验证”；无需虚构耗时、token、成功率。

## 4. 001：复杂业务系统专用路线

**理解业务**：角色/权限 → 关键任务与高频动作 → 页面地图和信息架构 → 导航方式 → 各页组件/状态 → 视觉 → 源码与运行。

至少核查：
1. 登录/门户/首页/查询/表单这些页面身份明确，页面清单与用户要求一一对应。
2. 菜单分类、横向溢出、折叠/展开、账号与退出、表格字段、筛选、分页、校验、空/加载/错/禁用态均与业务目标相符。
3. 操作是否形成闭环（点击入口→进入页面→操作反馈→错误处理）；静态稿只说明预期行为，不能宣称已实现。
4. 参考图的配色/布局/材质各有明确作用范围；锁定首页后不得把局部反馈变成“导航页重做”。

**关键失败触发**：用户指出“留白没解决反而换色”“登录框变得过大”“明明要图形却换成风景照”“顶部菜单箭头点不了”时应重新锁定原任务，修根因，不沿失败方向重新生成。

## 5. 002：复杂数据大屏专用路线

**理解场景**：屏幕物理环境与分辨率 → 关注问题/决策者 → 指标优先级 → 关系图与口径 → 画面分区 → 图表/告警 → 视觉空间 → 实际渲染。

至少核查：
1. 统计口径、时间、单位、图例、阈值、真实/模拟数据界限明确；图表数据与表示形式匹配。
2. 阅读顺序与观看距离合理：关键数值可读，信息密度不靠冗余卡片或装饰撑场面；大地图只在具有地理业务时使用。
3. 视觉立体感是材料、空间、层次关系，而非简单给外框加发光或改变蓝色亮度。
4. 不以虚构数字、误导图表比例或假实时跳动来丰富视觉，明确未接数据时的模拟标识。
5. 检查指定屏宽截图，无关键模块裁切；窗口缩放时数据和告警仍可辨。

**关键失败触发**：业务数据未给却出现“真实实时”数值、地图完全装饰化、原指定黑色大屏被套蓝紫、图表读不清时不得宣称设计完成。

## 6. 多轮协作：最短状态卡与失败回路

任务变更时只更新受影响的槽位：

```text
项目/UI员工：UI / 001或002
当前页面/版本：……
认可基线：文件或图片的可验证来源……
本轮唯一目标：……
必须保留：……
未通过项：……
刚完成的证据：……
下一次允许改动：……
```

同一轮能够完成目标，就直接交付，不强制输出卡片。长会话或跨任务迁移时卡片成为简短可复制摘要，**新会话仍要重新核验真实仓库/图片/状态**，不把摘要当最新事实。

如果两次连续未达标：①暂停沿失败版本追加装饰或换皮；②找最后已认可版本；③明确错的是哪一维（目标/布局/材质/颜色/业务/交付）；④只修该维；⑤重新运行对应关口。若工具无法保留非目标像素或无法读取源文件，说明限制，不假称精准还原。

## 7. 与现有规范的关系和能力边界

复杂设计完成后，如果用户还要求切图/素材和HTML，应进入 [语义切图与HTML交付流程](../skills/semantic-asset-export/SKILL.md)：先拆资产语义、导出透明图标与无前景背景，再将文本/交互绑定到HTML；不能把视觉方案的矩形区域截图当作组件资源并略过前端实现。

- 共同公约负责不可越界的用户指令、图片身份、风格编号、历史否定和正式交付。
- 需求理解 SKILL 负责解析用户意图、反馈指代、修改权限。
- 本复杂设计 SKILL 负责将多条件任务分层推进和保持版本/关口可检查。
- 001/002 专业 SKILL 负责业务系统/大屏领域设计与实现。
- `docs/INSTANT_DESIGN_QUALITY_GATE.md` 的 Q0～Q3 是最终验收底线，不因新的阶段名称被覆盖。
- 即时模式在复杂任务能否保持质量是**实测命题**。须在相同输入下运行 `docs/COMPLEX_DESIGN_REGRESSION.md`，记录真实图稿/源码/用户评价。出现关键失败需修复并复测，不能仅靠更新文档宣称通过。
- **图稿完整性与冻结区域差异是独立验收门禁**：每次高清PNG导出或用户认可图局部修订，加载 `skills/visual-fidelity-lock/SKILL.md`；实际输出检查100%可读性、目标画布、非目标区域差异与无关页面稳定性。区域外变化不允许通过重新调颜色、隐藏或更换整体背景来掩盖。
