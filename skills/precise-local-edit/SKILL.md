# UI 设计师｜局部精准修改与防需求倒退 SKILL V1.0

> **优先级**：用户本轮明确指令＋其指认的已认可原图 > 项目共同公约 > [共用需求理解](../design-requirement-understanding/SKILL.md)与[视觉冻结](../visual-fidelity-lock/SKILL.md) > 本SKILL。任何“优化设计/顺便协调/重新生成一版”都不能扩大用户授权修改范围。
>
> **触发**：只改一个下划线/一个词/一块颜色/一张图标/某个按钮/局部CSS，尤其用户反馈“只要A却把整张背景改色、把未点名文字改了、按错图版本、改完看不出变化、同一问题连续两次改不对”。001系统设计师与002大屏设计师均适用，无需再要求用户反复复制已有需求。

## 1. 三类身份分离：金样、最近错误版、目标图

- **认可基线 / gold**：用户最后**明确认可的版本**，承载所有应继承设计。纠错时不拿上一次失败稿替换它。
- **用户本轮引用的原图 / source reference**：可能是局部色彩/下划线的**特定样本**，不等于可以把原图其它页面、布局、颜色整体迁移。
- **待修目标 / candidate**：现有页面或最后一次输出。必须记录目标页面和当前真实源文件/图层版本、具体位置、旧失误、未通过项。多个参考图按用户说明的“第一张/最后一张”用途使用，不能按缩略图显示顺序替代。

**本次反馈的解释样例**（真实界面登录页，但不包含用户私有截图）：用户在某轮只要求“左侧CONNECT下方一条短横线改为参考图中更暗的效果”，时，若用户此前还明确说过“线条必须更贴近CONNECT文字下缘”，则**同时授权那条线的垂直位置与颜色/透明度/明度**（以真实认可原图的间距为标准）；CONNECT文字本身、欢迎词、左侧深绿背景、几何线框、右侧暖白登录区域和橙色强调/表单等全部冻结。后续用户说“你还是改亮了”“你把右边底色改了”时，这是否定错误输出而不是授权从错误版继续衍生。**必须以用户认可的未修改原稿重新施加同一处修改。**

## 2. 先形成微变更契约（不必让用户签字）

每轮内部记录六字段，执行者以文件、DOM或图片中的真实对象和属性填充：

| 字段 | 具体要求 |
| --- | --- |
| `baseline` | 已认可原稿/真实HTML源码/文件HASH或版本；不能使用失败版 |
| `target` | 精确至一个元素/层，如左面板CONNECT下方单条横线；多同名元素以DOM ID/区域坐标消歧 |
| `allowed_properties` | 合并本轮与尚未通过的既有明确要求；CONNECT示例为**线条垂直位置（贴近字母下缘）＋线条明度/颜色**。不可从用户简短的“仍没改”中丢失位置要求 |
| `protected` | 其余所有文字、图案、背景、左右面板、表单、比例、光影、位置、交互默认冻结 |
| `must_change` | 明确检查线条实际发生合方向变化；不能交同一张未改图 |
| `must_not_change` | 所有未获授权的其它像素/代码/视觉效果无差异；不能偷偷改字、改右侧背景、改左侧整体明暗 |

**闭环目标**：改动只在用户允许集合内；允许集合内的目标确实改变且方向正确；冻结集合内零未授权变化。**任一项失败都不能称任务完成。**

## 3. S0～S6 最小编辑工作流

1. **S0 引用绑定**：结合最近多轮反馈核实当前目标图与局部原图，记录已经纠正过的否定项。第一张/第三张是按**用户本轮的描述**绑定，而不是模型自己选一张“看起来更像”的图。
2. **S1 锁定目标属性**：把用户的“只要A”转成仅允许修改A的颜色/位置/大小等具体属性；用户只提颜色，严禁改A的尺寸/位置/造型，严禁改其它对象。
3. **S2 选择保真编辑手段**：有HTML/CSS/矢量源，**最小选择器/单独图层/变量**修改；有原始高分辨率位图可用独立图层遮罩/局部像素选区。**不要整图重生去实现一条小线**。若所用生成工具无法保证区域外不变，应改用可控编辑方式；无法实现时标`未通过`，不能拿全图随机重生成品当准确修订。
4. **S3 实施真正变更**：对目标进行可定位、可追溯的实际颜色/透明度修改，并把样本来源与色彩值/相对明度记录。**改前改后目标区域不能完全相同**；不得把“重新导出图片”当已经调整颜色。
5. **S4 源码范围核查**：如HTML/CSS文件，先读现有DOM/样式和git diff。确认只影响目标选择器/属性及必要资源，不修改其父容器的全局背景/共享token；若该token影响右侧登录页，必须拆出局部token以避免扩散。保留已存在的表单/文字/按钮/交互/其他文件，不得无关重排或格式化。
6. **S5 双层差异验收**：位图以原认可版本和本轮输出做同尺寸像素检查：**目标确有变化 + 改动方向对 + 非目标绝不变**；HTML在同视口、同状态、字体已加载条件下做源文件diff + 浏览器截图，冻结区域比较。不应在CSS“改了”但浏览器截图未变时宣称修正成功。
7. **S6 失败回退与交付**：出现新增全图改色、右侧背景变色、底线仍太亮、原未改等任一未通过项时，**废弃这一候选**，回到最近认可基线仅改目标；不在错稿上迭代错稿。交付时给出真正新图/页面、改动位置和属性、前后对照及非目标冻结证据，无法实际运行或下载则明确未测。

## 4. 精准色彩调整：CONNECT底线专项示例

- **“底线”与“底纹/字母”分离**：定位CONNECT下边**具体水平线**，不得把CONNECT大字、WELCOME标识、整体底纹线网或整块背景一起变暗。
- **“贴近CONNECT下缘”与“变暗”是两项并存的未通过要求**：将线条的上沿向CONNECT字形底部靠近，按用户认可原图的**文字下沿至横线的真实间距**对齐；与此同时保持参考线条的**暗度/色相**，不要只调颜色不挪线，也不要只挪线不调色。线长、线宽、字母、背景、右侧暖白登录区、橙色按钮、表单和其它图层冻结。仅当用户明确只改颜色且没有未通过的位置要求时，才保持线条位置不变。
- **位置变化的检验不能套用单向“darken”规则**：移动一根线会产生“旧位置恢复背景＋新位置绘制线条”两处合法像素变化；须把**原位置和目标新位置**分别设为窄小的允许ROI，并分别要求两处实际有变化（`required_changed_regions`）；此时对RGB差分的`color_direction`使用`any`，线色是否更暗另按认可原图样本/浏览器computedStyle独立查验。仍要保证除两处窄ROI外全图零变化。
- 用户反复强调“跟原图一样”，优先对**特定线条的视觉样本**对照：在相同底色上比较其可见深浅。不能以“我使用了原图”为由直接把整张参考图的其它元素粘到当前页面。
- 用户反馈“图像没有任何改动”时，原图版本与输出的目标ROI像素差/DOM计算样式差为0即自动失败。不得用语义上自称“变暗”替代真实结果。

## 5. 现有校验与新增强制关口

- 已有 `scripts/verify_ui_artifact.py --before gold.png --image output.png --region x,y,w,h --require-change` 可以发现**未改**和**允许矩形区域外发生变化**，但不能判断**颜色是否真的朝要求的方向改变**。
- 新增 [微变更方向与冻结区核验](../../scripts/verify_micro_edit.py)，以**事前确定**的目标细小矩形、保护区及亮暗方向判断，拒绝“没改、变亮代替变暗、整体改色、保护区域被动”。只在同源同尺寸PNG或同浏览器环境一致截图时有可靠的零容差意义。
- **HTML必须额外人工检查源码diff与真实页面截图**。像素相等证明图片未变，而不能证明CSS选择器未影响交互；如果目标图内部含文字，保护区域应覆盖文字以防误改。
- **禁止基于失败输出临时扩大可修改区域**以强行通过，也不能重新命名错误候选为“原图”。输出局部ROI对照、非目标变化数和目标方向检查结果，未获得可验证源则不得标通过。

## 6. PM-01～PM-12 回归用例

| 用例 | 必须发现或防止 |
| --- | --- |
| PM-01 | 只修改CONNECT下短线，输出仅该线略暗：通过微变更方向+范围检测 |
| PM-02 | 只修改线条却把左侧整个面板变暗：超范围失败 |
| PM-03 | 左侧局部要求改色，右侧暖白登录面板整体变灰：保护区与冻结区域失败 |
| PM-04 | CONNECT下线完全未变化，却回复“已修复”：目标变化数量为0失败 |
| PM-05 | 原线要求变暗，输出反而变亮：方向失败 |
| PM-06 | 改线条时把CONNECT大字颜色、字体或位置也变了：目标外/保护区失败 |
| PM-07 | 使用整图生成导致无关字体、表单和背景随机变化：冻结区失败，不当作精准修改 |
| PM-08 | 将前一张错误输出当新参考，越改越偏：引用基线错误，回退金样后重新执行 |
| PM-09 | 只允许改颜色却把线条加粗、延长、位移：源图/DOM属性差与微选区检验失败 |
| PM-10 | 用户第二次指出没改对，模型再次给相同图：要求变化及未通过项复核失败 |
| PM-11 | 原本的CONNECT字母、WELCOME、右侧表单被错误理解为同一改动对象：契约和保护区失败 |
| PM-12 | 已修改CSS源码但最终截图与之前一致或用户无法访问输出：视觉交付仍未通过 |

**限制**：本SKILL与静态合成测试只能检查可见约束是否被实际代码遵守，不能保证模型未来每轮都不误解；真实001/002任务还须凭文件、截图和用户验收逐项核实。

## 7. V1.1｜001 CONNECT 下划线“位置＋颜色”双目标阻断（补正原错误指令）

**已证实的需求理解遗漏**：先前将用户要求错误缩减为“仅下划线颜色/明度”，甚至在交接Issue中写了“坐标冻结”，使001即使遵守旧SKILL也可能无法实现“横线必须贴近CONNECT下缘”。本轮已明确更正：**位置靠近字母下沿、线色接近原图的偏暗效果，两项缺一不可。** 用户说“001还是一点变化没有”属于原任务持续未通过，不能因为这轮只有一句话就重置为“只需让任意一个像素变色”。

**001必须输出三组实测证据**：
1. **双目标前后对照**：认可原图与最终图同尺寸裁出“CONNECT字母＋整根线条”；提供已核实的文字下缘、线条上沿及两者的间距，证实新线**比旧版更靠近CONNECT且符合原图参考间距**。不能把线移到文字上、让其穿字，也不能暗换CONNECT字号或整体字形。
2. **颜色变化证据**：参考原图中线色在相同左背景上的实际外观，与候选新线的颜色/亮度对照；不能只降低全页亮度，不能因换背景得到“暗了”的假象。
3. **全页冻结证据**：除旧线位置和新线位置这两个最小ROI外，其它像素/DOM全部保持认可基线；真实HTML需补最小CSS diff、同视口截图。新增[两区域必须有变化的检测器能力](../../scripts/verify_micro_edit.py)能拒绝“只改旧线颜色没靠近/换图未改/修改其它背景”的伪完成。

**状态规定**：没有原始源PNG/HTML或不能从真实截图验证新旧线间距时，不得宣称已执行或验收；先在001真实会话查找源文件，确实没有才陈述限制。不得靠文字回复“已调整”替代真实新文件和对比证据。
