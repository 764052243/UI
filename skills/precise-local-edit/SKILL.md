# UI设计师｜局部精准修改与防需求倒退 SKILL V2.0

> **职责边界**：000维护跨页面、跨任务可复用的方法与验收机制。某张图的具体对象、精确位置、颜色值、源文件、返工结果和验收结论，由对应的001/002在自己的任务记录和真实工程中维护；**不在公共SKILL里追加单个缺陷的专项命令**。
>
> **优先级**：用户本轮指令与已认可基线 ＞ 项目共同公约 ＞ [需求理解](../design-requirement-understanding/SKILL.md)和[视觉冻结](../visual-fidelity-lock/SKILL.md) ＞ 本流程。用户纠错不是重新设计的许可。
>
> **触发**：用户要求仅改局部颜色、位置、文字、线条、图标或一个组件；或连续反馈未变化、反向修改、越权改色、错把失败稿当原稿。适用于所有系统页和大屏。

## 1. 角色分层与通用变更契约

- **认可基线**：用户最后认可的完整图稿或真实源码、版本与可核验的文件身份。不得自动升级失败候选为新基线。
- **外部参考**：明确标注仅参考哪些维度（例如局部颜色、形体、布局或材质），不扩大到整页。
- **本轮候选**：现存待修改版本及其真实源文件。先排除与本轮目标无关的旧错误版本。
- **未通过项集合**：追踪此前尚未解决的明确要求。后续用户仅说“仍不对/还没改”时，**保留整个未通过集合**，而非只保留用户最后一句的词语。

实施者在每轮执行前内部填写可核对的契约：

| 字段 | 通用含义 |
| --- | --- |
| `baseline` | 已认可的源文件、页面、版本与原始画布 |
| `target` | 被授权修改的具体对象/图层/DOM选择器 |
| `allowed_properties` | 用户当前明确指定以及尚未解决的属性集合（位置、颜色、透明度、尺寸等） |
| `protected` | 所有未获授权的页面、元素、布局、业务、交互与视觉属性 |
| `must_change` | 各个目标属性的可测目标状态及验证方法 |
| `must_not_change` | 不可改变的内容、边界与比对方式 |

**禁止两种过度约束**：把“只修改这个对象”误读为“这个对象以前的位置等属性一概冻结”；也不允许把“颜色不对”扩展成“整页重新配色”。属性范围应来自用户的全部有效要求，而非模板的默认假设。

## 2. PLE0～PLE6 通用工作流

1. **PLE0｜证据归位**：读取本任务真正认可的图稿、当前可编辑源、参考维度、实际用户反馈与未通过项；没有可信原件时标缺口。
2. **PLE1｜目标定位**：精确到页面/层/像素ROI/DOM元素；形成上述六字段契约，冻结非目标区域，不对用户已否定的设计换皮。
3. **PLE2｜选择精准手段**：源HTML/CSS优先最小选择器与局部变量修改；分层图用目标层；位图用局部蒙版/可信编辑。不能用整图随机重生冒充精准调整。
4. **PLE3｜真实实施**：源文件或图像必须实际改变，各个未通过属性均落实；若目标位置移动，应把**旧位置清除区和新位置出现区**都列入允许变更，而不是仅把新位置单侧圈为目标。
5. **PLE4｜源码范围审查**：核实变更文件、选择器/样式依赖、共享token及功能行为。共享样式修改波及其它组件时，应收窄作用域。没有源代码/图像访问权限不能宣称已改。
6. **PLE5｜双向验收**：必须同时证明**目标有变化且方向/属性达到要求**、**非目标未发生未授权变化**。用同源同画布PNG差分、真实HTML同状态同视口截图及源码diff。移动对象应检查旧位置和新位置，颜色、间距等语义指标需另行验收，不能仅凭“有像素变化”过关。
7. **PLE6｜失败回退与交付**：任一未通过项失败，状态仍为未完成；回到认可基线局部重做，不在失真候选上累计迭代。交付真实文件、前后局部对照、冻结区检查和仍未验证内容。

## 3. 验收工具的适用范围

- [微变更像素验证器](../../scripts/verify_micro_edit.py)：接受已认可基线与候选PNG、事先锁定的允许区域/保护区域，检测无改动、越界变化、可选的变亮/变暗方向。若涉及移动，使用`required_changed_regions`分别验证旧目标位置和新目标位置确有变化，并把颜色/间距等真实期望另做验收。
- [既有图稿检查器](../../scripts/verify_ui_artifact.py)：用于PNG资源自身及非目标变更检测，不代替实际浏览器和人工视觉检查。
- 对真实HTML/CSS：需做最小源文件diff、浏览器同视口截图、交互与布局回归。图片验证器不证明HTML可运行。
- 只有真实金样、原始素材和对应任务的实际运行结果才能证明目标达标；**工具的合成单测通过不等于用户具体图已经修复**。

## 4. 通用反回归用例 PM-01～PM-12

| 用例 | 通用验收规则 |
| --- | --- |
| PM-01 | 目标对象的被授权属性正确变化且完成目标 |
| PM-02 | 擅自改变同页其它背景、配色或布局：FAIL |
| PM-03 | 跨页面、其它组件被共享样式牵连：FAIL |
| PM-04 | 重新导出但目标像素或CSS实际效果未变化：FAIL |
| PM-05 | 属性变化方向与用户要求相反：FAIL |
| PM-06 | 目标邻近文字、图标或其它冻结元素变化：FAIL |
| PM-07 | 整图重生成导致无关区域漂移：FAIL |
| PM-08 | 把最近失败候选当作最新认可基线：FAIL |
| PM-09 | 只允许改颜色却擅自改变形体、尺寸或位置：FAIL |
| PM-10 | 遗漏此前仍未通过的另一项授权属性：FAIL |
| PM-11 | 有对象位置迁移但旧位置未清除、或新位置未出现：FAIL |
| PM-12 | 代码声称改变但真实浏览器结果未变，或交付文件不可用：FAIL |

## 5. 责任与发布门禁

000只改**可跨案例复用的规则、测试器、工具及回归机制**，并验证这些机制；不得用每次用户投诉的具体按钮、文字、色值和坐标不断堆积公共SKILL。具体设计返工由对应001/002完成并对用户交付。可以把具体现象留在原Issue任务记录中追踪，但Issue与000规范合并不代表设计师已被唤醒，也不代表该图已验收。

**质量红线**：必须逐个验证所有未通过属性的结果，而不仅是提交文件、运行通用测试或“看起来比以前好”。对缺少可编辑源/原图、无法实际执行或缺浏览器证据的项目，明确标记未验证。
