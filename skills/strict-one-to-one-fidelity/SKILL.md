# 严格1:1原图还原与切图资产证据 SKILL V1.0

> **适用**：用户明确要求「1:1、照原图、不许失真」；或对002大屏顶部KPI/左侧状态/底部业务图标连续指出颜色、透视、反射和发光与原图不同，或已经有完整设计稿却无法在HTML中复现。与[语义切图](../semantic-asset-export/SKILL.md)、[视觉冻结](../visual-fidelity-lock/SKILL.md)、[视觉回归](../../docs/ASSET_FIDELITY_REGRESSION.md)并用。**本SKILL中“1:1”是需要证据的验收结论，不是设计语言，也不是有类似质感就算。**

## P0：先把“原图”从比较截图里分离

1. **只接受用户认可的独立原始完整PNG/PSD/SVG或来源可追溯导出作为金样**。照片查看器窗口、浏览器标签栏、红箭头、鼠标、浮窗和缩略图叠加的**对比截图**只用于定位缺陷，不能作为像素级金样；不能从画中画的缩小原图重新放大/截图作正式原图。
2. 记录认可源路径/原生像素宽高/SHA256、色彩空间（优先sRGB）、页面名、设计版本、用户指定ROI和目标状态；保留原字节，不改色、不二次压缩，不把失败候选升级为新原图。
3. 新任务中如只有用户的对比截图而无独立原图，**可先做问题定位及不破坏原稿的规范修复**，但不得声称已取得符合像素逐点比较的原生金样。002应先在自身已有交付目录/会话中找真正原图，不重复要求用户提交已存在的文件；确实不可得则如实列缺口。

## P1：源图层与视觉目标分级，不能“画个差不多”

| 任务语义 | 优先实现 | 可称1:1的边界 |
| --- | --- | --- |
| **静态视觉预览1:1** | 无损使用原生完整PNG作为**预览或对照**（仅静态，不冒充语义HTML） | 相同像素画布、相同图像解码/色彩条件下可以逐像素一致；**不代表PNG图层已拆分或交互实现** |
| **独立语义PNG切图** | 原PSD/矢量/3D分层导出优先；缺源层时保真提取可见像素、边缘重构和严格复核 | 单张扁平合成PNG中的前景、半透明光晕和被遮挡背景**无法唯一无损分解**；可重建但须明确来源和不确定范围 |
| **真实HTML/CSS/JS复现** | 文字、按钮、交互必须是DOM；图标/立体组件按原图同位合成；必要复杂视觉用高保真透明组件 | 若没有源层、字体或真实动效数据，不能保证所有像素零差异；实际浏览器截图须逐区验收，无法通过则报告未达标 |
| **高清重建** | SVG/程序化2D/3D仅在缺少真正原图资产时使用；先提取形态、颜色、光影数值，再精确调参 | “4K清晰、可编辑”不等于“1:1一致”。任何新增创作、通用图库替代、线宽/色相/透视偏移不得以高清掩盖 |

**禁止**：把低清像素重绘成不同造型却称原样、将有独特几何/光影的视觉单元替换为通用模板，或用整页均值掩盖用户指定的任一关键局部差异。

## P2：视觉元素逐件锁定与双图对照

按任务实际组件建立关键元素清单，数量与区域由用户指定的目标决定，而不是由SKILL写死。**不同类型的组件分别验收**：小图标要核对轮廓、色阶与背景载体；指标图标要核对材质、高光与几何厚度；立体组合件要完整验收前景符号、实体底托、阴影、光晕及相对锚点，不能只通过其中一层就宣布整体通过。

**操作要求**：从用户认可原图按真实坐标取得每个组件原始ROI（应包括全部可见光影、阴影边界及文字关系）；在同一原始画布建立实际HTML截图对应ROI；放大显示 `Gold / Candidate / AbsDiff`，比较透视顶点、线条粗细、颜色、暗面、光晕长度、形体/字体/上下左右关系，**每一个关键部位单独过关**。ROI范围在看到修复结果前冻结，不能故意缩小到只剩形体中心。

## P3：数值与人工质量门禁并行，不能凭平均值冒充1:1

- 新增 [逐关键ROI严格原图一致检查器](../../scripts/audit_strict_1to1.py)：指定独立原图的SHA256、原图来源类型、原生分辨率、HTML渲染截图和**全量关键ROI清单**；不对任何输入重采样、旋转、自动对齐或改色。严格模式**逐像素RGB及Alpha零差异**才通过。每个ROI独立报告改变像素数/最大通道差/差异包围框；全页任务还应测全页。
- **系统功能验收与视觉差异独立**：即使全页像素一致，也不证明图标PNG透明、HTML使用了独立SVG/PNG、菜单可点、数据真实；分别沿用语义切图与HTML/ZIP质量门禁。
- 若源图包含文字、动画时间或系统/浏览器字体等不可避免的栅格差异，不得偷偷提高阈值后仍声称像素1:1；可以额外提交**允许误差的视觉对照报告**，但必须明确“**非严格逐像素1:1，未达成**”及位置原因，征得用户认可才可更改验收级别。
- 棋盘/白/黑底仅用来判图标的透明性和脏边，不可代替将图标放回**真实HTML原位置、原背景、原尺寸**的最终复合检查。背板有暗色并不自动是错误：须用原金样判断合法3D暗侧壁与新引入黑底。
- 高清仍要从真实源导出正确CSS×DPR的分辨率；**像素画布较大、不锯齿与实际忠实原图是三项分别核对**。

## P4：失败即阻断，停止重复交付类似图

提交前，002至少应提供：
1. **金样来源证据**：原始图名/分辨率/SHA256，排除包含红箭头、图片查看器的比较截图。
2. **逐件映射清单**：覆盖用户本次实际点名的**全部关键区域**，每处有ROI、原图裁图、候选截图裁图、误差与“还原/提取/重建”的真实资产来源。
3. **工程来源与组合证据**：独立PNG真实Alpha及原生尺寸、SVG/3D源（如重建）、实际HTML浏览器截图、运行结果、可解压ZIP；不能用整页截图当作有交互的HTML交付。
4. **失败处理**：任一用户点名关键ROI与金样不一致即本轮验收未通过；在源文件中只修那一项后重新跑逐ROI检查，保持已确认非目标区域不变。用户连续反馈同一问题时优先停止无依据的新矢量重绘，回归源图可见像素/原生图层与保真流程。

## P5：验收证据分类

| 层次 | 可声称的事实 |
| --- | --- |
| SKILL与脚本检查通过 | 规范和合成单测可执行，**不意味着当前用户的真实图像得到修正** |
| 真正原图与浏览器截图逐像素相同 | 仅证明**此图、此状态、此画布**静态像素一致 |
| PNG图标/底托/光影逐项还原 | 必须另外有人审源图层、透明边缘和独立资产含义 |
| HTML语义、交互与ZIP验收 | 必须实际运行、操作、检查资源和打包；截图相似不代表可以交互 |
| 原图只有截图且无法取得原生素材 | 可以继续真实高保真重建，但不能保证凭空恢复全部原始细节，也不能自称已达到严格1:1 |

本SKILL强调“**先保真、后高清；先用原有真实视觉，后在不可提取处局部重建；有证据才报1:1**”。不要求安装Photoshop；无PSD时也能做较高质量的重绘，但不得用重绘取代核验。
