# SKILL｜大屏与数据驾驶舱设计

> 共用前置：先读取 [需求理解与反馈定位 SKILL](../design-requirement-understanding/SKILL.md) 与 `UI_DESIGN_CONVENTION.md`，确定本轮用户指向的图表/模块/画布区域、允许变更的维度和必须保留的设计基线；不得把留白、图表密度或比例问题自行翻译为换配色。
> 复杂任务加挂：多指标多来源、工艺流程与空间关系、多图参考、严格还原、多分辨率及复杂交互的驾驶舱，先按 [复杂设计分层 SKILL](../complex-design-instant/SKILL.md) 分解数据语义、指标权重、构图与视觉验收；不得因 Instant 省略数据和画布核验。
> **图稿交付硬门禁**：任何大屏设计PNG导出、已认可稿的局部改动均加挂 [高清与锁定区域保护 SKILL](../visual-fidelity-lock/SKILL.md)。核对目标分辨率、100%像素下的数值/图例/轴标签和观看距离可读性；不允许用小图插值放大伪装4K，不得改动用户未点名的图表、颜色、材质、指标和其他页面。

## 1. 适用范围与触发

适用于数据大屏、数据驾驶舱、指挥中心、态势感知、工业监控、能源监测、运营监控、实时数据展示墙等任务。主体是全屏数据阅读、监控或指挥决策时加载本 SKILL。若任务还包含登录、后台管理、查询表单等系统页面，系统页面另加载 `skills/system-ui-design/SKILL.md`。

## 2. 设计目标

大屏不是把后台页面放大，也不是把装饰铺满屏幕。核心目标是让目标用户在指定观看距离和显示设备上，快速识别整体态势、最重要的核心指标、指标之间的关系与变化、异常告警和需要采取的行动。视觉冲击必须服务于信息理解，不能牺牲数据准确性和可读性。

## 3. 需求分析

识别使用场景、观看方式、画布比例和分辨率、数据内容、用户关注点及交互要求。用户指定分辨率优先；未指定时可先按 16:9、1920×1080 制作候选稿，并标注该假设。缺少真实业务数据时使用明确标注的示例数据，不得把虚构数据包装为真实数据。

## 4. 大屏风格方向

本节 BS01—BS07 是**大屏场景/构图任务标签，不是新的主风格编号**。主风格库仍为共同公约固定的 F01—F12；仅在用户明确「选择风格」且为自主创作时展示 F 菜单与每种风格各一张独立原创参考图。已有获授权样图可复用，缺少归档图片时在当前任务现场生成示意图；不能生成要明示，不得用伪链接。

- **BS01｜经营分析驾驶舱**：核心经营指标、趋势、结构和目标完成情况；适合管理层决策与经营复盘。
- **BS02｜综合指挥中心**：全局态势、核心区域、事件流、资源状态和处置进度；中心区域必须承载真实业务信息。
- **BS03｜工业设备监控**：设备、产线、工艺流程、运行状态、告警和实时参数。
- **BS04｜地理空间与网络态势**：地图、区域关系、节点连接、流向和空间分布；地图必须表达有效信息。
- **BS05｜数据叙事与汇报大屏**：标题、关键结论、对比图表、时间线和说明；适合专题汇报、政策展示和成果发布。
- **BS06｜空间层次可视化**：前中后景、透视、体块、材质和光影；实体效果不得遮挡图表、标签和数据。
- **BS07｜轻量清晰运营屏**：清晰分区、适度层次和高信息效率，适合长期运行、密集监控与多指标浏览；不是无层次的二维图形拼贴。

风格不是固定模板。不得只更换颜色形成不同方案。

## 5. 画面组织方法

不要固定套用“顶部标题 + 左右小卡片 + 中间大地图/球体”的套路。先根据数据关系选择总览型、流程型、地理型、设备型、对比型或叙事型构图。避免平均切成大量等尺寸卡片、小字过密、大面积无业务意义的空背景和无意义装饰。

## 6. 数据可视化规则

指标名称、数值、单位、统计口径、时间范围清晰；图表类型与数据关系匹配；颜色语义一致；图例、坐标轴、刻度、标签和交互提示可读；趋势和占比不误导；告警等级、阈值和异常状态区分明确；不伪造实时跳动、随机数字或虚假告警；多数据源标注来源和更新时间。

## 7. 造型、空间和颜色

造型表现与配色分开决策。需要更强空间感时，通过结构分层、前后景、透视、体块、材质和光影实现，而不是只加渐变或发光。需要清爽或高可读性时，也不能把画面简化成缺少层次的二维图形拼贴。

不默认深蓝、蓝紫或霓虹色。严格遵循用户指定的参考图、品牌色和场景要求。深色、浅色、暖色、中性色都可以成为合理方案。

## 8. 设计与实现流程

梳理指标和数据关系→确定画布、观看距离和栅格→选择与数据关系匹配的主构图→设计图表、指标、告警和辅助信息→建立颜色、字体、间距、图表和状态规范→制作完整画面→如需代码按项目技术栈实现→使用真实或明确标注的模拟数据验证。

## 9. 实现验收

检查目标分辨率下没有关键内容裁切；远距离核心指标可识别；数字、单位、图例和时间范围准确；图表比例和数据关系正确；告警与正常状态区分明确；动画不干扰阅读、不制造虚假实时状态；目标分辨率变化时布局合理。真实运行与截图验证分别记录。

**精准局部修改同样适用**：002若收到“只改一条线/一个图标/一处色彩”，必须加挂[局部精准修改 SKILL](../precise-local-edit/SKILL.md)的最小变更契约，确保用户认可的其它地图、指标、光影和布局冻结。用[微变更检查器](../../scripts/verify_micro_edit.py)拒绝无改动、反向调整或非目标变色；不能因为操作对象在大屏就整体重建。

## 10. 参考图与交付

**严格1:1复现通用门禁**：用户明确要求1:1或反馈局部严重失真时，加载[原图身份与逐关键ROI门禁](../strict-one-to-one-fidelity/SKILL.md)，使用[严格差异检查器](../../scripts/audit_strict_1to1.py)。从用户认可的原生完整图取得所有实际指向的ROI（不预设数量或组件类别），比较形体、色彩、立体厚度、光影与真实HTML同位效果；带查看器窗口、箭头或缩放的拼图不能充当原生金样。无源层可保真重建，但不得将更高清的近似图宣称严格像素1:1。

**色彩/材质/HTML视觉居中通用门禁**：当图标色阶、材质或HTML对齐与认可金样不符时，执行[CF0～CF7颜色与DOM可见中心专项](../../docs/COLOR_FIDELITY_HTML_ALIGNMENT.md)、[原图ROI颜色与布局检查](../../scripts/audit_color_layout.py)及[浏览器Alpha几何采集](../../scripts/capture_ui_alignment.js)。各目标组件按真实金样颜色和独立视觉槽逐一验证，不得用统一主题色、加锐化或仅CSS盒子居中替代视觉保真。

**立体复合单元通用门禁**：所有存在底托、实体侧壁、前景符号、阴影、外发光的视觉单元，按[HG0～HG6立体光晕与黑边专项](../../docs/VISUAL_UNIT_GLOW_REGRESSION.md)分别建源图层并保留锚点，禁止将暗色实体误删、把页面背景混入图标，或按普通glyph自动裁断光晕。使用[同视口逐单元ROI复合校验](../../scripts/audit_visual_unit_composite.py)，没有真实HTML与原图证据不得宣称还原通过。

**无PSD也必须继续高清切图**：002只有1672×941等扁平合成大屏、没有PSD/3D源层时，必须执行[无PSD高清重建SKILL](../source-free-hd-reconstruction/SKILL.md)：导航/业务符号用SVG可编辑矢量重绘，立体底托/地图使用程序化SVG/3D重建，输出满足实际CSS×DPR的独立PNG并在HTML同视口对照认可原图；不得继续放大43×48小截图、以缺PS为由停止或擅自改变造型配色。**重建的高清质量和与认可原图一致是两项独立验收。**

**底部业务图标＋蓝色3D底托是完整视觉单元**：底托单独PNG只代表组件层，用户需要完整业务图标时必须提供完整复合PNG，或以glyph＋plinth＋完整组合预览及HTML实际渲染证明完全还原。遇到半个底托、低清、毛边必须启用[Photoshop级源层精修SKILL](../photoshop-grade-asset-extraction/SKILL.md)的R0～R7；优先PSD/PSB/矢量/3D源层重新导出，不得用小位图简单放大称高清。

> **切图任务强制加挂** [语义切图、PNG图标与HTML交付 SKILL](../semantic-asset-export/SKILL.md)：大屏的独立导航/状态图标必须是透明PNG，背景应优先用CSS高保真还原简单深色/渐变；**只有确实需要图像的背景或用户明确要求PNG背景时**才从原图层输出完整背景PNG（不能纯黑/半幅冒充复杂原底）；复杂地图、3D底托及不可替代纹理作为独立组件，依据[资产角色与边缘质量](../../docs/ASSET_ROLE_AND_EDGE_QA.md)判断哪些该切、哪些不该切；如果用户要求HTML，必须交实际 index.html + CSS + JS，并验证资源引用与交互，不能把一张总览图分成25个带字矩形就称资源切图完成。**切图后还须以用户认可的原版大屏作金样，执行 [F0～F5视觉一致性及RV回归](../../docs/ASSET_FIDELITY_REGRESSION.md)**，特别检查顶部导航图标轮廓/光效、中央地图与多层立体底座、左右图表模块、底部立体服务图标和HTML渲染后的比例层次。纯透明PNG/HTML存在但与原图视觉不一致仍为未通过。**大屏导航与底部服务图标必须逐一通过 [I0～I5紧裁、内容居中与保光晕检查](../../docs/ICON_ASSET_ALIGNMENT.md)**：不得留大片多余透明边、不得图形偏移，不能仅靠外层CSS居中；严禁误裁原版立体底托、阴影和发光。使用 `scripts/normalize_ui_icons.py` 对目录每张PNG检查或非破坏性归一化，最终还要回到认可金样做视觉核对。**用户再次指出黑底残留时，必须先执行 [B0～B4 前景/背景/底托语义分离](../semantic-asset-export/SKILL.md)：导航/指标/业务图标里的深色面板不能作为 PNG 图标本体，黑色立体底托应独立做组件并在 HTML 还原；Alpha框居中但前景符号偏心属于未通过。**

参考图目录 assets/style-previews/big-screen/ 只登记真正获授权的样图，不得编造链接。风格菜单的 F01—F12 独立参考图要求按共同公约执行；没有仓库归档图时生成会话内原创示意图（不自动归档），不能生成须报告缺项。交付遵守共同公约：独立完整 PNG、必要源码和资源、ZIP；核实文件、图片解码、ZIP 完整性和 HTML 运行状态。用户侧下载未验证时如实标记。

## 11. 大屏数据审计与视觉验收门禁

开始前逐项核对指标名称、数值、单位、统计口径、时间范围、数据来源、刷新周期、阈值及告警等级，并区分真实值、测试值和无法确认项。所有数字、图表、比例和告警应可追溯到输入资料或标明模拟数据。地图、网络关系、工艺管线必须表达真实数据关联，不能只作装饰；没有地理/空间业务则不能自动强加中国地图、地球或中心球体。

锁定用户指定的屏幕比例、分辨率和观看距离。未指定可提出 1920×1080/16:9 候选假设，但不能以默认假设覆盖原图严格还原的比例；还原要优先补背景边缘而非重排主体。控件、标题、图例、趋势、告警和切换必须能在目标显示设备阅读，不能以局部发光、轨道、大量装饰网格替代业务内容。

数据可视化的自检项目：主指标视觉优先级明确；异常比正常更易识别但不过度闪烁；图表轴、范围、图例、单位不误导；空间/流程/布局与数据关系吻合；实时更新只有真实数据事件驱动或明确标注模拟；不同数据源更新时间可辨认。动效不可制造不存在的实时事件。

## 12. 设计模式、基线与交付边界

对“下方太空、主体不饱满、显示不满屏”等反馈，按共用需求理解 SKILL 优先定位具体图表/画布和栅格问题，不增加虚构指标或无意义发光装饰。用户是在询问原因时先解释；明确要求修改时再动手。纠错后重新处理原问题，不以错改版本为新基线。

先识别严格还原、精准修改、自主创作，再应用本 SKILL。已认可的整张大屏图片是主视觉基线；不能把它降级成“深蓝科技参考”而重新生成另一套驾驶舱。只修改用户指定图表或区域，图中的其他模块、布局、材质、配色、文字及交互必须保留。没有源文件、仅能重建时须说明是“重建候选”，不得称原版修改或像素级复刻。

交付独立高清页面 PNG；需要切图时每张/每个组件分别输出并核验。源码验收不仅核对静态画面，还应检查数据绑定、缩放裁切、状态/告警、图例以及目标分辨率下实际运行截图。未连接真实数据或无法实机测试必须清楚标记；文件存在、图片解码、ZIP 完整和用户实际可下载是不同验收状态。

## 13. 即时模式设计质量关口（002 专项）

交付前依据 `docs/INSTANT_DESIGN_QUALITY_GATE.md` 的 Q0～Q3 核查，不因采用 Instant 降低原有标准：

1. **看的是正确画布**：锁定指定分辨率、比例、页面和认可基线；“下方太空”须找到具体图表区/指标区，不擅自重做整个场景。
2. **业务数据可靠**：核对指标名、数值、单位、统计时间、图例、阈值、告警状态；没有可靠来源标明模拟，不能用虚构趋势、数字、地图或管线填补空白。
3. **视觉真实有效**：对照分区主次、文字远距可读性、信息密度、留白、空间关系及材质；不是只加深蓝、霓虹、发光边框、巨大球体或3D装饰。
4. **交付与渲染证据**：目标分辨率下内容不裁切，图表轴/图例可辨，图片可解码；动态数据或实际交互未接入则明确“未实现/未测试”，不得冒充实时系统。
5. **回归用例**：至少覆盖 `docs/INSTANT_DESIGN_REGRESSION.md` 的 VQ-07～VQ-12 适用项及需求理解 RQ-06；用户否定某种构图后，不得换色重复其本质结构。
