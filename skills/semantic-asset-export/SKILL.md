# SKILL｜语义切图、PNG 资源与 HTML 还原交付 V1.0

> **触发条件**：用户提到「切图、PNG图标、PNG背景、提取素材、前端还原、HTML源码、页面ZIP、组件图/背景图」任意一类，001/002 **必须加载本 SKILL**。若用户继续指出不高清、边缘脏、只剩半幅/半个底托、分层后缺图标，**先核验是否有可编辑源图层**：有源稿则加载[Photoshop级/等效源层精修SKILL](../photoshop-grade-asset-extraction/SKILL.md)；**只有扁平合成图、没有PSD/矢量/3D源时，强制加载[无PSD高清重建SKILL](../source-free-hd-reconstruction/SKILL.md)并继续制作SVG/程序3D的可编辑高清素材**，不得以缺少PS或源图层为由结束任务。两条路线均须完成可用PNG、完整视觉单元、浏览器金样复核；禁止拿低清裁片放大冒充高清。用户同时要求多项时完整交付，不允许自行删减。优先级：用户本轮明确要求和认可原图 > UI_DESIGN_CONVENTION.md > 本 SKILL > 一般建议。
>
> **失败反例**：将一张完整大屏截图按矩形裁成「顶部区域/左下区域/中间地图」等多个带文字、图标和背景的块，然后宣布“切图完成”；只有一堆 PNG 和清单、没有真实透明图标、独立背景、HTML。这种矩形分块**不是用户要求的 UI 资源切图**。
>
> **边界**：只有一张扁平合成位图，无法凭空恢复被图标/文字遮住的真实背景、分离原有的高质量分层素材；不得谎称“无损提取”。允许结合原图重绘单个图标、修复背景遮挡，但须说明是“重建/补全”而非原始图层提取，并检查与认可基线的视觉一致性。

## 1. 首先判定交付意图，不按“切成几块”理解

- **整页视觉预览**：一个 `preview/full-page.png`，用于对照，不替代资源。
- **PNG 独立图标**：每个图标/状态单独 `assets/icons/*.png`，**RGBA透明背景、紧贴图形、适当透明留白、无文字/导航面板/灰黑底块**。图标本身如包含发光/投影应保留真实半透明边缘，不能扣成硬边，也不能把背景黑色误带进来。
- **背景图（仅确实需要PNG时）**：纯色/深色渐变/规则纹理、按钮底色、纯色圆盘等优先CSS，**无必要不切PNG**。用户明确要 PNG 背景或有不可替代的完整纹理才输出`assets/backgrounds/*.png`；必须是完整背景层与正确画布，不得半幅/纯黑替代复杂原底，不能包含文字/按钮/指标。无法恢复遮挡时从源层导出或标记重建不确定区。
- **复杂视觉组件**：`assets/components/*.png`，用于不适合用 CSS/HTML 等价复现的复合装饰/设备/地图组件。**原稿中特殊斜切角、四边明暗渐变、局部发光且构成一个整体的面板框也属于独立`ornamental_frame` PNG组件**，不可退化为HTML简单`border`；简单规则线条仍用CSS。任何组件不得直接截入本应是DOM的可交互文字、图表、菜单和数据。
- **HTML+CSS+JS 页面**：`index.html`、`css/style.css`、`js/app.js`，**真正用 HTML DOM 实现标题、菜单文字、按钮、指标、图表容器、交互**，以相对路径引用真实 PNG 资源。不得用 `<img src="full-page.png">`、整页 `background-image`、canvas 单张截图或把多个矩形区域图拼起来冒充可运行页面。
- **ZIP**：打包完整预览、独立图标/背景/必要组件、页面源文件和资源清单，文件结构可解压、路径有效、页面入口明确。用户只要求素材切图不要求 HTML 时按用户需求；但**一旦用户明确要求 HTML，缺 HTML 就是未完成**。

## 2. 切图前从已认可的图建立语义资源表

把每个元素归类为 `background`、`icon`、`component`、`text`、`interactive`、`chart`，并列出其唯一 ID、原图位置、目标导出尺寸、是否透明、预计使用位置、HTML/CSS/JS 归属。

- **先做资产必要性判定，再做图层分离**：复杂地图、真实3D底托与不可替代纹理才是优先PNG候选；简单背景/规则圆盘/按钮底板/文字通常由CSS/HTML负责，不能为凑数量全切。顶部按钮/标题中文字在HTML中呈现，独立icon PNG只留前景符号。
- **文字必须尽量真实可选中、可读、可更新**；用户要求的文字、数字、指标、按钮/菜单不允许全部烘焙到矩形 PNG。
- 视觉复杂但有业务含义的地图/图表，优先 HTML/SVG/Canvas 数据绑定或透明独立组件；若只能提供静态图，明确标为静态组件，不能冒充实时图表。
- 列出各图标的普通/选中/悬停/禁用等必要状态；不允许一张含多状态的横向 PNG 代替多个独立图标（用户明确允许 spritesheet 除外）。
- 只能从源图“矩形裁切”时，须识别裁块是否含不应附带的文字、周边边框、背景；无法独立扣取就标记未达标并回到源文件/重绘，而不是改名为“图标.png”。

## 3. PNG 的真实规范

- 图标：PNG 文件格式，模式含 alpha 通道（RGBA/LA 或带透明信息），**必须存在真实透明像素与真实可见图形**；alpha 外围留合理安全边，防止 glow 裁切、边缘白边、黑底脏边、锯齿、错位。
- 背景：**只有选择image策略时**才有整页背景PNG，必须匹配画布、真正全幅且不带前景UI。**选择css策略时不强制背景PNG**，完整页面背景由CSS实际实现。整页背景默认不透明；需透明叠加的视觉内容属于component。
- 分辨率：优先从可编辑图层或原始高清稿直接导出；低清截图插值放大不算高清重建。图标按使用位置提供足够像素密度，实际 DOM 展示时避免拉伸变形。
- 文件命名：短、语义化、稳定，如 `icon_nav_overview_active.png`、`bg_dashboard.png`、`deco_map_glow.png`；不只用 `01_顶部区域.png` 等没有资产语义的名称。
- 交付的图标、背景及组件须有**资源映射清单**，列清楚每张资产在哪个 HTML/CSS/JS 部位被引用，避免“切了很多但页面没用”。

## 4. HTML 必须真正还原并可操作

1. 建立可运行的 `index.html` 页面，优先按实际设计画布建立主要栅格结构、标题、图标按钮、图表区和状态区。用户要求交互时，菜单切换、hover/active、折叠、筛选或页面跳转必须有真实事件；未接后端则明确模拟数据。
2. `css/style.css` 引用背景 PNG，`img` / CSS 引用独立 PNG 图标。HTML 标题、菜单、指标文本可选中，不得只作为截图的一部分。可使用 SVG/Canvas 实现需要响应的图表，但不能把整页画成唯一不可交互的背景。
3. `js/app.js` 保留已确认的导航与交互逻辑，只实现已明确的行为，不虚构业务功能。**写出源文件不等于已经运行成功**。
4. 全屏大屏按用户指定 1920×1080 / 3840×2160 等真实目标画布设计；查看实际浏览器视口截图，检查文字清晰、布局、图层、溢出、图片引用、交互焦点和核心数据。背景层 `z-index` 不得覆盖文字/按钮的可点击区域。
5. 用户要求 1:1 还原时，视觉基线不可擅自变更；遇到静态图难以恢复的图形，先尽可能使用透明独立资源/高保真重建，不以换风格的 HTML 替代。未能逐项还原的部分逐条标注。

## 7. 错误纠正与状态报告

用户指出“图标不是透明的、背景没单独做、HTML没给”，必须将 S1/S2/S3/S5 标为**未通过**，返回已认可原图重做资源与页面；不要只给裁块重命名，也不要因修复切图顺手改变原图配色/布局/文字。回复分别列出：真正交付的 PNG 类别与数量、HTML/CSS/JS 文件、ZIP 文件、实际验证命令与结果、未验证及风险。不能声称用户已经成功下载。

**严格1:1返工的额外门禁**：当用户明确指出切出的PNG与已认可图反复出现轮廓/材质/发光失真，必须读取[严格1:1还原SKILL](../strict-one-to-one-fidelity/SKILL.md)，对每个用户指向的KPI/状态/底部业务单元分别使用**真正原生原图**ROI和实际HTML同位截图逐件零差异门禁；已有画中画截图只用于标注缺陷，不可代替原稿。独立语义PNG的Alpha和HTML互动与视觉1:1是三项各自验收，不能用一整张原图静态铺底伪装完成。

## 8. V2.0：以用户认可的第二张图为唯一视觉金样（Golden Master）

本次真实反馈：切图/组装版虽然输出了图标和图片，但与用户认可的**第二张效果图**在造型、光效、布局、完整度和最终画面上差异明显。此前的 S0～S5 主要核查“资源存在、HTML引用、PNG透明”，**不能证明还原后的视觉一致性**。从现在起，切图任务在 S0～S5 外必须执行下述 F0～F5 **金样一致性门禁**；用户指出不一致后应标为失败，**不得拿错误的第一张做新基线**。

- **F0 金样锁定**：以用户明确认可的原图/当前指定图作为唯一视觉对照，记录文件、尺寸、色域、版本、批准来源。截图中的“第二张”按用户上传顺序辨认；无完整文件先检查会话附件、可访问项目素材与交付源文件。不能用裁切预览、低清图、上次失败输出、重新生成的“同风格”图替代。
- **F1 图层与资产来源**：逐一标注 `extracted`（来自原始可编辑图层）、`masked`（从位图抠取）、`reconstructed`（依据原图重建）。从扁平截图分离出的图标/背景不得假称无损；地图、底座、玻璃、半透明发光、图标投影需要分别决定图层和叠加顺序，**禁止截图拼贴替代透明图层**。
- **F2 独立资源逐件核对**：每张 PNG 对照原图同一位置的视觉特征，核对图形轮廓、线宽、透视、厚度、亮度、色相、发光外扩、阴影、透明羽化与安全边。多个图标必须各自核查，**同一套发光图标不能换成统一“扁平线稿”**。原图有底座/实体厚度时，资源必须按相应组件分别表达，不可缺失。
- **F3 画面复合与几何定位**：确定 CSS 画布与用户基准图的**共同真实视口**，明确原点、每个资源的渲染框、内边距、缩放、锚点、`object-fit`、`transform`、`z-index`、混合模式、阴影及层级。禁止用整体缩放/拉伸去掩盖局部错位。地图主体、底座、边栏和各个顶底模块必须分别对齐；**重叠、遮挡、断层、裁切、错位、文字覆盖**均为失败。
- **F4 全页金样对照**：实际在浏览器指定尺寸渲染 HTML 截图；与原金样并排/重叠核对，按**顶部品牌与导航、顶部指标、左右面板、中央地图与立体底座、底部服务区、文字图标与光效**划分关键区域逐项核查。可用 [视觉对比脚本](../../scripts/verify_visual_reconstruction.py) 与[检查计划](../../docs/ASSET_FIDELITY_REGRESSION.md)报告全页和关键区差异；两张尺寸不同必须先在原始源/同视口重导，**脚本不做自动缩放**。指标不能用“综合平均差异小”掩盖地图或导航局部严重失真。
- **F5 修正并重新回归**：把“图标缺失/轮廓错误/黑边、底座变薄或消失、地图变形、文字偏位、导航高宽错、渐变或高光损失”等按区域记录为未通过项；一次修一类根因，从原金样/正确源文件更新，不以失败图继续重生。直到 S0～S5 与 F0～F5 的适用项均满足、浏览器实际运行、用户视觉验收，才能称交付完整。

### 图标细节的专项验收

**不能只用「PNG有alpha」就算合格**：如果 PNG 在透明背景下看起来正确，但放回深色页面后出现白边/黑圈、模糊光晕、锯齿、图标被裁、厚度变平、中心偏移、图标与文字比例失衡，仍判不通过。检查透明图层在深色和浅色底上的预览；避免未预乘/预乘 Alpha 混用，避免从 JPEG/截图中抠出残留底色；PNG导出时检查图形与 Alpha 轮廓、原始光源关系和阴影像素。原版有复杂立体实体图标时，优先从源图层提取或人工矢量/三维重建，再独立透明导出，不能只用 CSS 图标库替代。

### 背景、地图与底座的专项验收

从合成位图“删除前景”会暴露原本被挡住的区域；**隐藏内容不存在可逆像素信息**。必须取得原始背景源文件，或依据相邻纹理/层次重建并标注不确定处。要求独立背景时，背景不能残留按钮、数字和导航标签，也不能因抹除产生大片模糊块。中央地图/立体底座/光圈等高关注组件要保留**光源、体块高度、橙蓝发光边、透视、遮挡次序和光影投射**，无法达到基准时明示不合格，而非改成简单二维图形蒙混。

### HTML视觉一致性不能用图片结构合格代替

静态资源目录、DOM存在、点击事件可执行不代表**画面像第二张**。必须在实际浏览器渲染后按 F4 比对。接受的不同主要来自用户明确允许的动态数据/时间变化，不能自动豁免文字、地图、导航、材质等关键区域。对动态值可在测试环境冻结时间/数据/动画为基准状态，但不能为了遮盖缺陷直接屏蔽或变空。每个关键区域的验收阈值与预期宽高应**在调整候选稿之前确定并保留记录**，失败后不可放宽阈值或改小检查区域以“通过”。

**最终交付格式**：`preview/reference-accepted.png`（仅有授权且确实可提供时）／`preview/html-render.png`、`reports/fidelity-report.json`、资产类型与来源表、可运行 HTML/CSS/JS、完整 ZIP。原始用户金样属于用户素材，未经授权**不得上传公共 UI 仓库**；在当前任务会话的工作目录私有校验即可。没有原图则写“F4 未验证”，没有浏览器实跑则写“F4/S4 未验证”，任何一项关键缺失均不得宣称高保真还原完成。

## 9. V3.0：逐图标“去多余空白＋可见主体居中＋原样保真”强制门禁

> 任何任务中，即使输出PNG且含透明通道，也无法单凭文件存在证明**图形自身裁边、大小与视觉居中**正确。每件独立前景图标都应按本节验收，不以文件数量、CSS外层居中或系统缩略图代替真实PNG检查。

**定义分开**：
- **素材级紧裁（tight trim）**：以 PNG 的真实 Alpha 有效包围框为边界，**仅删除外侧多余透明空白**，保留图标本体、底托、微弱外发光、软阴影、半透明抗锯齿边缘。不能因裁空白而削掉原金样的光晕、立体厚度或装饰。
- **素材级居中（alpha-bound centering）**：紧裁后可见主体包围框左右、上下透明边距基本对称；**PNG 本身必须居中**，不允许靠 `margin-left`、CSS 绝对定位掩盖内部偏移。
- **界面级居中**：PNG 在 HTML 所属图标容器内再用 flex/grid `align-items:center; justify-content:center` 等真实居中规则；根据已认可画面的图标视觉尺寸设置 CSS width/height，`object-fit:contain`，不拉伸、不切边。PNG紧裁与 DOM 容器对齐是两次不同验收。
- **视觉重心复核**：Alpha包围框居中**只是几何前提**。若图形本体不对称（偏重的地图、卡车、人物、徽章、发光底托），仍要按认可金样检查**视觉重心**和图标与标签的垂直基线；不得用自动计算“居中”声称人眼已通过。

### I0～I5：交付前逐 PNG 验收

| 关口 | 必须实际核对 | 失败判定 |
|---|---|---|
| **I0 原件锁定** | 当前用户认可金样与每个图标原件可对应；先保留源文件，标注原图层提取/位图抠图/重建 | 改用上次失败图、未核对来源就批量输出 |
| **I1 真透明** | 实际 PNG RGBA Alpha 包含透明和可见像素；暗底、亮底对照有无黑白脏边、残留背景与伪影 | 用 RGB/不透明白方块或带菜单条的截图冒充图标 |
| **I2 紧裁透明空白** | 检查所有非零 Alpha 的有效包围框；删除仅外侧冗余空白，通常留约 2px 安全边，视实际微弱光晕适当调整 | 内部左/右/上/下留几十像素空白，或紧裁时切掉光晕、底座 |
| **I3 PNG自身居中** | 计算紧裁后四侧透明边距及其偏差；边距上限默认 `max(2px, ceil(短边×4%))`，左右/上下差上限 `max(2px, ceil(短边×2%))`；不合格不得入最终包 | 图标明显贴左/贴上，即使HTML容器本身居中 |
| **I4 还原与UI摆放** | 按金样逐件检查造型、体积、底座、描边、发光、实际显示尺寸；HTML图标槽的居中、标签对齐、实际浏览器截图 | 为了统一裁边而改变图标比例/放大拉伸，或把立体图标变扁平图标 |
| **I5 交付证据** | 每个最终 `assets/icons/*.png` 有检查报告（尺寸、Alpha框、四边空白、居中状态、预览结论）；ZIP重检所有实际引用图标 | 只抽检一个或“图片文件都存在”，遗漏任一失败图标 |

## 10. V4.0：黑色底块与假居中通用根因门禁

> **未通过问题**：`assets/icons` 里的部分图标仍带黑色背景区域；部分视觉主体偏移。之前只看“PNG存在Alpha”“Alpha矩形紧裁和居中”，甚至 F0～F5 都没有阻断**图形与背景烘焙在同一图片**的情况。**以后先剥离语义图层，再谈裁空白、居中**；不能再次用 Alpha 裁剪解决黑底。

### 切图角色重定界（本节优先于旧版“I2裁空白”解释）

1. **`assets/icons/icon_*.png` = 前景符号**：例如人物、货车、闪电、立方体、导航标志的发光主体，**真正独立透明**。不允许混入原卡片黑色矩形、面板底色、按钮背景、圆形深色衬底及不属于符号的3D平台。
2. **`assets/components/*.png` = 立体底座/业务复合图形**：如果原金样有蓝色发光底托、黑色实体厚度、橙色边缘，应把它们独立保留于 `components` 或使用精确 CSS/SVG 还原，再由 HTML 原位置叠加；**不得为了“去黑色”把金样的真实立体底座删除**。用户明确要求“含底座的完整图标资源”时可额外交复合版，但需**同时交单独前景 icon**，不能以复合版替代独立图标。
3. **`assets/backgrounds/*.png` = 纯背景层**：卡片底板、圆形黑底、导航激活面板等不是图标；由 CSS 或单独背景/组件资源实现，页面视觉效果与金样一致。
4. 如果只有扁平截图，黑色底与发光符号已经混成不透明像素，**Alpha紧裁无法删除背景**，必须从源图层导出，或对符号进行可验证的遮罩提取/高保真重建。不能粗暴“所有黑色变透明”，否则会连立体阴影、描边和黑色有效结构一起误删。

### B0～B4：先语义提取、后居中

- **B0 判定边界**：逐件参照用户已确认原效果，列出“图标前景／背景黑块／真实立体底托／阴影光晕”，不按图像的颜色一刀切。若无法确定某黑色区域是否属于符号，标记待人工确认，不把错误图标打包。
- **B1 反黑底验证**：在棋盘、白底、深色底三种背景下查看每一个 PNG。**检查实际 Alpha 及边缘像素、深色不透明矩形、黑白残色、暗色块与邻区、填充角落**。有透明像素但黑矩形仍不透明属于**关键失败**。
- **B2 来源级分层**：优先从原源文件把前景符号、发光阴影、底托、面板分别导出；若遮罩提取/重绘，则标为 `masked` / `reconstructed`，逐一对照已认可金样验证轮廓与材质。无原素材不能称无损。
- **B3 分层后重新紧裁居中**：仅在**去掉不应存在的背景图层之后**，以真正前景符号 Alpha 包围框裁外侧透明边并使主体在**独立 PNG 文件内部**居中；不要拿包括黑底或底座的“大矩形”计算中心冒充前景居中。HTML 再按图标槽定位和对齐；不缩放变形。
- **B4 视觉金样回归与失败隔离**：生成逐图标三底色 QA 联系表，逐项标“底块清除/符号居中/光晕完好/金样一致”；CSS/HTML在同一视口合成还原真实底托与前景。**任一图标不通过，不得声称图标资源质量合格**。

## 11. V5.0：必要资产决策、完整背景与毛边阻断

**重要修订：本节对早期“背景PNG是默认必选项”的表述具有解释优先权。** 不是要求所有背景都必须切出来。用户认可的画面结构、材质和光影不可降级，但能由 CSS/DOM 高保真实现的底色、规则渐变、KPI圆盘或导航切角，**不应为凑PNG数量独立导出**。

1. **P0 先分类**：逐元素写出 `html_text / css / icon / component / background / preview` 及其用途、是否必要切PNG、重复资源能否复用；只导出必要的 PNG。中央地图、3D底座不属于小型 `icon`，而是高保真 `component`；可复用业务底托只需一套，不要五套仅文件名不同的图片。
2. **P1 背景真实性**：复杂背景如果原源图层拿不到，不得将“整屏截图抠除文字”再以纯黑/半幅/大块透明的 PNG 冒充背景。纯黑/简单渐变用CSS；独有纹理和复杂光影需从可编辑源层导出，或如实标识重新构建并通过金样。用户点名要求背景PNG则必须提供真正全幅正确内容。
3. **P2 完整图层**：地图、本体、立体底座、环形发光边、阴影等按真实层级导出。**主体只剩一半或有效光晕、结构被裁断，不得进入交付包**。复杂3D结构不要因为拆分方便被“简化成半个椭圆”。
4. **P3 边缘质量 E0～E5**：源图完整 → 独立遮罩/真Alpha → 无黑白污染的抗锯齿/半透明边 → 无内容碰裁边/缺角 → 棋盘/白底/深底和100%/200%/400%细节核查 → 浏览器同画布金样复验。对图标和复合素材逐一检查毛边、锯齿、黑色脏边、糊和贴边截光；**不能把仅“存在透明像素”当作无毛边证据**。
5. **P4 资产映射与复用**：清单写 `reason_png`（为什么必须用PNG）、`source_kind`（原图层/抠图/重建）、`background_strategy`（CSS优先或真正图像）、`edge_policy`（组件是否明确允许贴边）。不允许使用空泛理由绕过不必要素材；用户明确要求不可被清单字段抹去。
6. **P5 双层检查**：打包前使用 `scripts/verify_ui_delivery.py` 的 `schema_version=1.1` 检查背景策略、非必要资产和组件裁边；使用 `scripts/audit_asset_edges.py` 生成逐件Alpha和三底色对比。**两个脚本不能保证抠图无毛刺或3D形态准确**，仍须对照原认可大屏人工逐件检查，并运行HTML截图F0～F5。

完整优先级、示例清单、边缘技术定义和 AR-01～AR-14 回归案例见 [切图资产判定与边缘质量](../../docs/ASSET_ROLE_AND_EDGE_QA.md)。新任务优先填写 `schema_version: "1.1"`，只允许旧版 `1.0` 作为历史兼容；不能以旧脚本默认“必须有背景PNG”为理由继续导出纯黑空白图片。

**重要边界**：效果图或资源管理器截图不能证明原始PNG Alpha、蒙版和HTML运行状态。通用规范与检查器测试通过并不代表任一具体项目已修复；应由任务对应的001/002读取真实源文件、PNG和浏览器产物，记录逐项验收。

## 12. V6.0：立体底座不能被自动紧裁；用浏览器同坐标ROI阻断黑边与残缺光影

通用Alpha几何紧裁、SVG文件存在和整屏平均RGB差异通过，都不能证明复合视觉单元的透视、柔性光影、暗色实体与原图一致；涉及分层立体图时必须单独验证真实合成。

- **明确工具适用范围**：`scripts/normalize_ui_icons.py` 仅用于**可独立紧裁的前景glyph**，不能直接对 `plinth`、`shadow`、`glow` 和需要锚点的`component`自动裁边、居中或重采样。之前为“居中”裁掉底座辉光、改变透视坐标是禁止项。
- **把内容分为3类**：纯符号`glyph`、保留完整厚度的3D实体`plinth`、柔性辉光/投影`glow`，共同形成需要与用户金样对齐的`visual_unit`。如果一张可编辑SVG/3D源能原生完整导出`composite`，优先交完整单件，同时可另外提供可复用独立图层。
- **黑色的语义鉴别**：真实3D实体侧壁可以是黑/深蓝色；截屏/抠图时粘在轮廓外的暗背景、半透明边缘RGB污染才是错误。不要“全黑变透明”，也不要用整幅模糊假修复。先从矢量几何/材质层导出正确Alpha与抗锯齿；低清截图反复抠图不再接受为高清。
- **完整保光晕**：重绘时保留外发光的空间范围与柔和Alpha递减；有效Alpha含微弱像素，图形边缘与画布要有安全距离。若原版辉光延伸到组件之外，必须在可编辑源中留足画布，而不是把不完整切图裁得更紧。
- **真实浏览器ROI证明**：对应设计师应提供用户认可原图与同视口、同DPR、**仅当前待验视觉单元隐藏**的浏览器underlay；按HTML真实像素坐标叠加PNG运行`scripts/audit_visual_unit_composite.py`，逐单元输出`GOLD/COMPOSED/DIFF`，验证图层越界、Alpha贴边与RGB差异。不得临时缩放或平移素材通过测试，也不得以整页均值掩盖任何一个用户指定的关键单元失败。
- **执行记录**：参考图身份/ROI范围、可编辑SVG或3D源路径、PNG Alpha/边缘质量、每个视觉单元实际坐标、proof-sheet、脚本结果、人工100%/400%结论及未通过项；任何一张关键底托光晕或图标仍变形，不能称高保真切图完成。

完整的 **HG0～HG6**、同坐标ROI配置和 **HGR-01～HGR-12** 见[立体底座光晕与黑边专项](../../docs/VISUAL_UNIT_GLOW_REGRESSION.md)。缺少实际可运行HTML或underlay时标记未验证，不得声称背景、边缘或原图还原已通过。

## 13. V7.0：切图原色与真实HTML可见居中

**通用风险**：矢量图更高清、PNG透明或CSS设置居中，都不代表素材与认可金样的颜色、材质、边缘和页面可见主体位置一致。必须从真实参考图核对，不能套固定主题色。

1. 金样以用户**当前任务明确认可的原生图稿**为准，不能拿文件夹缩略图或失败HTML做色彩样本。每个图标记录原图ROI、实际sRGB主色/渐变与合法阴影/边线，以相应RGBA/渐变重建；不能自动套预设颜色。
2. 区分真实3D暗面与从截图抠图残留的黑色外圈：硬轮廓需要干净矢量路径与正确抗锯齿，柔性辉光单独保留；不要为了去黑边把底座实体或原始暗色描边全部擦掉，也不得整体加锐化/噪点制造破败质感。
3. 对所有图标角色明确HTML**视觉槽slot**。图标左、业务文字右的卡片，以专属icon槽居中，而非整个卡片；PNG透明留白可能令可见主体偏心，必须从真实像素Alpha包围框得到**可见中心**。保留原图已确认的偏移，不强制所有图标中心都等于卡片中心。
4. 用[浏览器几何采集脚本](../../scripts/capture_ui_alignment.js)捕获真实DOM和PNG Alpha范围，以[原图色彩+HTML对齐检查器](../../scripts/audit_color_layout.py)逐图标比较原图与候选HTML相同ROI内彩色/亮色像素的RGB误差及整块ROI变化，同时验证可见主体对所属slot的中心误差。
5. **自动检查通过仍不得宣称金样1:1或无毛边**：逐件100%/400%检查图标轮廓、材质、蓝/橙辉光渐变、透明边缘和HTML真实显示；用户再次指出色彩不一致时列为未通过项继续修复。不得通过扩大阈值或更换金样绕过。

完整规则、示例采集与CR-01～CR-12见[图标色彩和HTML视觉居中专项](../../docs/COLOR_FIDELITY_HTML_ALIGNMENT.md)。**规范/工具改动并不等于具体HTML已运行、已修复或通过视觉验收**。

## 14. V8.0｜整体装饰面板边框的PNG语义切图（FBG0～FBG6）

**适用任何UI**：用户认可原图中，面板四边和拐角是**同一个装饰视觉单元**，存在局部明暗、斜切转角、镀铬高光、软发光、多重细线等细节。**这些框不是普通CSS `border`可以替代的**。应作为`assets/components/frame_*.png`完整透明PNG组件导出；纯色、规则单线边框仍可CSS实现，不要求所有面板都额外切PNG。

- **FBG0 语义判定**：从原稿确定每个复杂面板的**整圈边框/标题装饰/光影**是否连成一体，登记`role=component`、`component_type=ornamental_frame`。不把左、右、上、下四条边随意独立拼合，也不把含数字、图表/标签的面板截图当边框。
- **FBG1 取完整源层**：优先原PSD/SVG/3D框层导出，覆盖全部边角、上下左右暗亮变化、外光晕，留Alpha安全边；只有扁平位图时不能通过普通矩形裁切真正分离边框，需透明遮罩/矢量精修并标记`masked/reconstructed`来源。框内合法暗边不可一键删黑。
- **FBG2 保真边框PNG：纯框、零背景、零图标**。一份`assets/components/frame_*.png`只表示**完整外圈边线、拐角及其真实光晕**，窄边带以外的Alpha必须为0；不能包含面板底色、顶部实心背景、半透明内部底纹、任何标题/导航/箭头图标、数据或文字。**与面板关联的每个图标另切独立透明`assets/icons/icon_*.png`**，以HTML原位叠加，二者不能混到同一PNG；四侧四角与原稿暗亮结构均须完整。
- **FBG3 HTML正确装配**：底色/背景层在下，**完整PNG框覆盖原位**，真实DOM文字/图表和交互在上；框层`pointer-events:none`，禁止加另一层CSS实线描边造成“双边框”。固定尺寸按原稿原比例展示；尺寸可变时，只有允许切分的框才使用PNG`border-image`/9-slice（**依然是PNG绘制，不是单色CSS border**），验证边沿亮暗接缝和四角不拉伸。
- **FBG4 manifest新增字段**：采用`schema_version=1.1`，用户明确需要的框ID列入`required_frame_asset_ids`。对应组件必须有`component_type=ornamental_frame`、`frame_inner_rect=[left,top,right,bottom]`、`frame_perimeter_px`（限制有效Alpha只在窄周边带）、`frame_icon_asset_ids`（与边框独立的图标ID清单，零图标用`[]`）、`frame_render_strategy=fixed_overlay|nine_slice`；九宫格还需`frame_slice_px=[top,right,bottom,left]`。每个关联图标都必须以`role=icon`独立PNG声明与实际引用，现有`source_kind/reason_png/edge_policy`继续执行。
- **FBG5 两层校验**：执行[scripts/verify_ui_delivery.py](../../scripts/verify_ui_delivery.py)先阻断缺框PNG/未引用/内区或非周边染色/四边四角缺失/关联图标未独立成PNG/错误九宫参数，再对照透明棋盘检查**框PNG只有纯边框、图标PNG只有独立图标**，最后在真实HTML原视口截图逐面板比较完整边框与图标的原位复合。工具通过不能证明形体、颜色、材质已1:1。
- **FBG6 交付**：保留可编辑原框源、完整PNG、manifest、HTML/CSS/JS、浏览器复合截图及ZIP，明确框PNG在何处被引用；若缺源层导致仍无法精确分离，标为尚未高保真还原，不能把HTML`border`替代当作解决。

完整通用规范、示例HTML和FBR-01～FBR-15回归见[装饰面板框整体PNG与HTML叠层验收](../../docs/ORNAMENTAL_FRAME_ASSET_QA.md)。**已确认设计只修改边框实现，不顺便改面板内容、颜色、尺寸、地图或其它无关组件。**
