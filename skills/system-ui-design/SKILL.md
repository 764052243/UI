# SKILL｜业务系统与产品 UI 设计

> 共用前置：先读取 [需求理解与反馈定位 SKILL](../design-requirement-understanding/SKILL.md) 和 `UI_DESIGN_CONVENTION.md`，锁定用户本轮实际指向的页面、区域、问题维度及不允许变更的部分，再执行业务 UI 方法。用户提问、反馈或纠错不是自动换风格/改色授权。
> 复杂任务加挂：多页面/状态、不同用途参考图、严格还原、导航交互与源码联合交付、连续纠错等情况，先按 [复杂设计分层 SKILL](../complex-design-instant/SKILL.md) 拆出业务关系、页面骨架、视觉和交互验收；仍按本专业 SKILL 落地，不需让用户逐项审批。
> **图稿交付硬门禁**：任何系统设计PNG导出、已认可稿的局部改动均加挂 [高清与锁定区域保护 SKILL](../visual-fidelity-lock/SKILL.md)。100%检查中文、导航、表单/表格小字、图标和完整页面尺寸；仅更改用户点名的组件/属性，检查相关DOM/CSS影响和非目标页面。若图像工具不能保留非编辑区域，不能把重生成称为精准修改。

## 1. 适用范围与触发

适用于企业管理系统、政务平台、财政预算系统、SaaS 产品、统一门户、登录页、系统导航、工作台、业务表单、查询列表、审批流程、管理后台和多页面 Web 应用。主体是用户通过页面完成业务操作时加载本 SKILL。若任务还包含数据大屏或指挥中心，另加载 `skills/big-screen-design/SKILL.md`。

## 2. 设计目标

让用户准确、快速、低负担地完成业务，不是把所有页面做成卡片集合，也不是只追求装饰效果。必须理解用户角色与权限、页面任务和关键操作、信息架构与导航路径、字段数据校验和状态、页面上下游关系、高频操作、异常处理和反馈机制。

## 3. 系统 UI 风格方向

SU01—SU08 是**系统业务场景/组织方式标签**，不可覆盖共同公约既定 F01—F12 风格含义；仅自主创作且用户明确要求「选择风格」时展示 F01—F12 完整固定目录、推荐 3—5 种，并为每一种分别展示独立原创参考图。仓库有获授权样图可复用，缺失则在本次会话制作，而非只标“暂无”作为完成菜单。

- **SU01｜政企专业业务系统**：规范、清晰、可信、信息密度与操作效率；适合政务、财政、预算、审批、公共服务和企业管理。
- **SU02｜现代 SaaS 产品界面**：产品化排版、精细组件、清晰层级和统一交互状态；适合综合工作台、应用管理、团队协作和企业服务。
- **SU03｜品牌门户与统一入口**：品牌识别和系统入口组织并重；入口必须清楚、可操作，不能只有装饰。
- **SU04｜空间化应用导航**：通过结构、几何、透视或实体模块表达系统关系；不能机械套用中心球体、漂浮小卡片和装饰轨道。
- **SU05｜专业深色控制台**：适合运维、监控、专业工作站和高密度状态管理；深色不是所有科技或管理系统的默认颜色。
- **SU06｜编辑式与品牌化工作台**：排版、非对称组织、内容节奏和品牌辨识度。
- **SU07｜温和自然商务界面**：舒适阅读、柔和层次和低刺激视觉；适合长时间办公。
- **SU08｜精致材质与微立体控件**：细腻材质、控件层次、轻高光、按压反馈和阴影；不自动扩展为厚重玻璃或复杂 3D。

## 4. 页面类型与布局策略

- **登录页**：明确品牌、产品名称、身份认证和登录操作。背景服务于识别，不遮挡表单；不得擅自更换指定配色或布局。
- **门户与导航页**：先识别系统数量、入口层级、分类关系和使用频率。导航形式可以是列表、分组、蜂窝、矩阵、画廊、空间化入口或其他合理构图；不能为了视觉效果强行使用六边形、环形、中心球体或轨道。
- **工作台首页**：围绕待办、任务、常用入口、统计摘要、最近访问和提醒组织；不机械堆叠等尺寸指标卡。
- **查询与列表页**：筛选、查询、结果数量、表格、排序、分页、批量操作和空/错/加载状态清楚。
- **业务表单与详情页**：按业务步骤分组字段，明确必填、只读、校验、错误提示、保存和提交状态。
- **多页面系统**：先建立导航和页面关系，再分别设计每页；不能把登录页、工作台、查询页都套成相同卡片模板。

## 5. 结构层次与空间表达

根据任务使用结构分层、空间构成、实体造型或复合表达。不要把简洁理解为所有内容都做成二维图形拼贴；也不要把质感理解为必须增加玻璃、发光、渐变或 3D。空间和材质不得降低文字可读性、点击准确性或业务效率。

## 6. 色彩和品牌

没有系统 UI 的固定默认蓝色。用户参考图或品牌规范优先；只指定配色时不改变其他确认设计。颜色、空间层次、材质和科技氛围分别判断。建立品牌色、辅助色、背景、表面、文字、边框、交互和状态色 token。

## 7. 组件与交互规范

按真实业务选择导航、表单、表格、筛选、分页、操作按钮、危险操作确认、加载/空/无权限/失败/成功/禁用状态、消息提示、弹窗和抽屉。组件视觉状态必须完整，不得只绘制默认态。交互说明与实际实现保持一致。

## 8. 参考图与严格还原

先识别参考图是还原基准、整体风格、配色、布局还是局部组件参考。用户要求 1:1 还原时，严格遵守共同公约，不得自行改版或以“优化”为由替换设计。只要求配色时只迁移色彩关系；要求整体风格时才迁移造型语言；不得擅自复制参考图业务布局。

## 9. 迭代与页面锁定

用户指出“选项卡下面留白、内容没铺满”时，先检查选项卡容器高度、内边距、内容编排和空间平衡，不将布局问题误解为配色问题，也不靠无关背景装饰遮掩。纠错后首先处理原问题；具体执行共同需求理解 SKILL 的定位—归因—修复—复验流程。

每轮明确当前页面、版本和修改范围。用户说改首页就只改首页；说改蜂窝导航就只改蜂窝导航。未点名页面和已认可区域保持不变。禁止自动切换目标页面。否定套路按本质特征禁止换皮重现。

## 10. 设计与实现流程

确认页面清单、角色、关键操作和参考图用途→梳理信息架构与业务流程→提出有实质差异的构图→建立颜色、字体、间距、图标和组件 token→完成完整页面→按需实现代码→实际运行并检查导航、表单、表格、状态、滚动和资源加载→按共同公约完成文件与链接验收。

## 11. 风格参考图与交付

在只有低清扁平原图、没有PSD的情况下，001应执行[无PSD高清重建SKILL](../source-free-hd-reconstruction/SKILL.md)，以可编辑SVG/程序化图形重绘图标并输出高清PNG与真实HTML；不得因无Photoshop拒绝实现，也不得用通用图标库替代用户认可图形。

用户指出系统图标颜色偏离参考、黑色描边、CSS虽居中但可见图形偏心时，启用[CF0～CF7颜色与HTML可见主体专项](../../docs/COLOR_FIDELITY_HTML_ALIGNMENT.md)，按金样ROI保持颜色/光影层次，使用实际DOM中的图标视觉槽和PNG Alpha可见框验证位置，不能仅因元素盒子居中判通过。

用户明确要求完整图标而拆分成glyph与底托时，必须额外交付完整视觉单元复合图和实际HTML截图；如果出现“分层后只剩一半、边缘毛刺、糊”，按[Photoshop级精修SKILL](../photoshop-grade-asset-extraction/SKILL.md)回到可编辑图层/矢量源进行非破坏式提取与R0～R7验收，不能通过放大已有小PNG伪装高清。

> **切图任务强制加挂** [语义切图、PNG图标与HTML交付 SKILL](../semantic-asset-export/SKILL.md)：图标独立RGBA透明PNG；纯色/渐变/普通按钮背景优先CSS，只有真实必要或明确要求PNG的背景才独立完整导出，并按[资产角色与边缘质量](../../docs/ASSET_ROLE_AND_EDGE_QA.md)检查切图必要性、缺层及毛边，业务文字/按钮/菜单由HTML DOM呈现；用户要求前端源码时必须交 index.html、CSS、JS 与实际引用资源，验证导航/表单状态，禁止只交矩形区块PNG。**图标PNG及最终HTML须以用户认可效果图作金样，执行 [F0～F5视觉一致性验收](../../docs/ASSET_FIDELITY_REGRESSION.md)**，逐项核对图标轮廓、材质/发光、组件位置和DOM实际渲染；透明PNG存在或结构检查通过不代表视觉还原通过。**每个系统图标按 [I0～I5规范](../../docs/ICON_ASSET_ALIGNMENT.md) 去除多余透明边并确认图形在 PNG 自身居中**，再在实际 DOM 图标槽居中；不可用CSS位移掩盖偏心文件，不能切掉微弱光晕/投影。**对图标PNG里仍嵌有黑色/白色面板底块的，先按 [B0～B4语义分层](../semantic-asset-export/SKILL.md) 提取纯前景符号，再裁空白与居中；黑色不是可一键透明化的颜色，原有立体阴影需保留为组件层。**

菜单的 F01—F12 独立参考图要求以共同公约为准；系统场景分类 SU01—SU08 仅用来组织专业方案。仓库 assets/style-previews/system-ui/ 没有对应已归档图片时如实说明，优先生成本轮原创示意图供选择（不自动归档），不得编造 URL 或用无关图片代替。交付时每个页面单独 PNG；按要求提供 HTML/CSS/JS、切图和资源；ZIP 只含本次确认成果。核验文件存在、图片解码、资源引用、ZIP 完整性和页面运行状态。用户端下载成功未获验证时必须明确标记。

## 12. 业务红线与页面实现门禁

结构化系统必须以完整功能页面为主体，不是“几张卡片铺在背景上”。先画完整业务信息架构：角色/权限→任务入口→导航层级→内容和字段→操作步骤→状态反馈→数据流转。用户已给的模块、菜单、指标、筛选、表格列、按钮、文案、字段及其关联均锁定，未经授权不得增删、拆合、重排；同样不得改校验、提交、跳转、权限或业务行为。

系统实现需核对真实 DOM 结构、组件 props、ID/class、事件、路由、API、状态机、脚本加载顺序与资源引用。精准修改时只动目标文件和选择器，保留周边样式与逻辑；只改颜色不重做布局；只改左侧背景图形不替换成风景照片、不重排右侧登录表单。不同页面之间相同的品牌规范与组件状态可共享，但登录、门户、工作台与查询页不得复制同一构图。注重桌面与常用窄屏响应式、键盘/焦点、加载/空/错误/禁用、无权限和提交中状态。

设计视觉效果要真正从分区、几何、体块、材质、层级、前后景与节奏形成，不因“现代”而自动纯平化，也不把“科技”理解成深蓝霓虹、轨道、巨大球体/四菱形漂浮、厚重玻璃六边形或空洞舞台。用户已否定的 R1—R4 只作失败反例，不作为后续改色、换背景的复用基线。

## 13. 参考图身份、锁定与精准迭代

严格遵守共同公约第十四节：用户上传图片批次序号不受截图内部小图或助手生成图片影响。用户说“第二张很好”即锁定该整张图，不能只取风格/颜色；后续只改点名区域。以这张图制作其他页面时保留原设计语言与空间构成，业务页面身份、流程、字段按本轮任务替换。没有可保留其他像素/结构的编辑能力时说明局限，不得从描述重生成另一张图冒充修改。

若用户要求 1:1 严格还原，不自由优化；完整保留构图、材质、反射、玻璃、光影、比例、文字与业务内容，画幅变化优先延展边缘。用户只指定某图配色时仅按其色域、明度和面积关系迁移配色，不迁移其他布局或组件。用户仅指出“颜色错了”则局部修色，不改业务与交互。

## 14. 验收证据与交付格式

验收清单按页面数量与名称逐页建立：业务字段数量/位置、导航入口、查询提交、权限与状态、参考图、构图、配色禁用项、材质、交互和适配全部检查。若只有静态 PNG，明确“未实现 HTML/JS”；若已生成源码但未运行，明确“运行未验证”；仅提供 ZIP 不等于用户侧下载成功。交付前检查独立 PNG 解码、无白边/裁切、真实图标资源、相对路径、ZIP 清单与完整性；源码需在测试环境实际操作按钮、表单、跳转等后才能称功能通过。

## 15. 即时模式设计质量关口（001 专项）

交付前依据 `docs/INSTANT_DESIGN_QUALITY_GATE.md` 的 Q0～Q3 核查，不因采用 Instant 降低原有质量标准：

1. **页面身份/版本正确**：首页、导航、登录、查询等各守其用；“继续改首页”不能切换到其他页。对照当前认可版本，而不是上一轮错改的图。
2. **内容与操作完整**：顶部菜单超宽须有实际左右切换或明确说明静态视觉方案；侧栏折叠/展开状态、退出按钮、通知、筛选、分页、保存提交等按用户要求存在且位置准确。
3. **视觉真正解决问题**：留白、间距、结构、空间层次、配色分别核对；用户只说“留白不合理”，不能擅自换颜色或大幅修改其他页面。
4. **渲染与交互证据**：有源文件时核对变更范围，运行并检查目标状态、长菜单、不同视口、真实点击/跳转与资源加载；没运行只说“源码已生成，尚未运行”，不得把设计图算成业务功能通过。
5. **回归用例**：至少覆盖 `docs/INSTANT_DESIGN_REGRESSION.md` 的 VQ-01～VQ-06、VQ-10～VQ-12 的适用项；用户指出新增错误时形成未通过项，修好后再次核对锁定内容。
