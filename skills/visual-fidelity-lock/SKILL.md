# SKILL｜高清设计与非目标区域冻结 V1.0

> 适用于 UI001 业务系统、UI002 数据大屏；与共同公约、需求理解、复杂设计分层和专业 SKILL 同时使用。**只要要交付设计图或修改已认可稿，就必须执行；简单纯文字咨询无需加载。** 用户当前明确指令与已确认的整体视觉基线始终优先。
> 本 SKILL 不允许把“高分辨率”冒充“视觉清晰”，也不把“类似旧图的重生成”冒充“只改这一处”。无原始资源、不能精确编辑或无法对照时如实列未通过项。

## 1. 两条硬门禁

**HD：高清可读。** 用户明确的尺寸、比例、显示屏优先；没有指定时在设计任务卡中标明所选目标画布及依据（桌面常见 1920×1080 仅是候选，不是强制默认）。需要高分辨率预览时，优先在设计源文件按适当倍率**重新导出**，而非简单放大一个小缩略图后称“高清”。最终必须有独立、完整可解码的 PNG；不能交聊天缩略图截图或压缩预览冒充正式成品。**图像尺寸通过不代表文字/图标清晰通过**。

**LOCK：已确认无关区域不动。** 用户认可整图后形成不可擅自替代的视觉基线。每轮明确目标页、目标区域（像素框/组件/DOM范围）、可变属性（位置/高度/配色等）、冻结区域/属性；未点名的其他页面、模块、颜色、材质、业务字段、图形元素与交互默认保持原样。修正 A 不得顺手调整 B；“为协调”不能成为未授权变更理由。若调整 A 依赖 B，先说明依赖及影响并取得授权。

## 2. 动手前找到正确基线

按当前指定附件或源文件 → 最近用户明确认可版本 → 项目可访问文件 → 交付包版本记录顺序确认来源。图片编号按用户上传批次真实顺序，不能把聊天缩略图或助手生成图重新排序。

- **代码/矢量源可编辑**：复制或新建版本（不覆盖已确认原件），限定被允许的组件/图层/选择器。保证修改前后能重现同一画布和状态。
- **高质量原始位图可编辑**：尽可能进行局部选区编辑。保存原图；编辑后比对选区外像素。图像生成工具不保证非编辑区域像素不变；实际有差异就不能叫“只改目标区域”。
- **仅有缩略图、压缩聊天图或截图**：不能凭空恢复真实细节。可以制作**重建候选**或重新按源图做高清重绘，但不能宣称是原文件的精确局部修改或 1:1 像素级一致；先如实区分局限。
- **用户要求整页重做**：将用户明确解除锁定的范围单独记录；其他未授权区域仍受保护。

## 3. 清晰度验收（与输出方式无关）

交付前对**实际最终文件**执行：

1. **身份与尺寸**：文件非空、能完整解码、页面数量和文件名正确；PNG 宽高、宽高比与用户指定目标一致。无需将所有图强行改成 16:9，不裁切主体换尺寸。
2. **100% 实际像素检查**：标题、正文、按钮、图例、轴标签、中文/英文/数字/单位无明显模糊、叠字、错字、乱码、重影、锯齿和裁切；文字细节不被过强光效、低对比度或背景纹理淹没。
3. **整页阅读检查**：在目标显示尺度下检查导航、模块主次、内容密度、边缘完整、色彩和空间层级；对大屏需额外从实际观看距离验证重点指标和告警。
4. **分区放大检查**：对高密度表格、长菜单、图表图例、玻璃反射边缘、图标、透明图层分别裁切放大观察。局部清晰不能掩盖整图模糊，反之亦然。
5. **导出来源与诚实性**：记录导出画布、方式（直接从源稿导出/位图重建/低清插值放大）、最终实际宽高；仅插值放大不称“细节恢复”。若无法检验某项则标“未验证”，不能写清晰度已全面通过。

没有唯一可靠的“模糊度阈值”适用于全部艺术背景；自动尺寸/解码检查属于**必要非充分条件**。必须结合真实视觉观察，尤其是文字、局部图标与非主体区域。

**严格原图1:1附加门禁**：原图必须是已认可的独立本地原生文件，不是聊天里的缩放缩略图、看图软件窗口或标箭头的对比拼图。仅有合成原图时若不可无损恢复分层组件，应区分静态像素外观与独立PNG/HTML的可维护还原；按[严格1:1还原SKILL](../strict-one-to-one-fidelity/SKILL.md)与[逐ROI零容差审计](../../scripts/audit_strict_1to1.py)验关键小组件，单个失败不得以整页均值或高清放大掩盖。检测不能自动证明美术品质、Alpha与HTML交互。

## 4. 锁定区域比对验收

**像素编辑**：以原认可位图与候选图相同宽高为前提，记录“允许修改区域”矩形坐标；可用 `scripts/verify_ui_artifact.py` 比对**修改框以外是否有任何像素变化**。默认 0 容差；选区外出现变化即未通过。仅用户授权调整整图时才扩大可修改范围，不得在差异出现后偷偷扩大选区使测试通过。

**源代码编辑**：比较真实文件 diff 与 DOM/CSS/JS 范围；用同一视口、相同数据和状态生成改前/改后截图，再比对非目标组件。排版级联可能影响邻区，必须检查而非假定“只修改一个选择器就不会变其他区域”。必要时通过区域裁切、锚点对齐消除渲染偏差；不同机器的抗锯齿差异不能直接当作授权改动。

**图像重生成**：如未能保留非目标区域，即使“肉眼看起来类似”也不能宣称精准改动；必须回到可精确编辑的原件处理，或如实报告技术限制和需要用户决定的替代方案。

图片整体重新布局/换色、文字或图标丢失、业务字段变化、其他页面被改、底部新加无关装饰、局部修复造成非目标区域被裁切，均属于**关键失败**。有实际比对的证据才可说“冻结区域保持一致”；没有源图不能声称已验证不变。

## 5. 实用验证脚本与使用示例

**涉及 PNG 图标、背景切图或 HTML 源码时，还必须加载 [语义切图交付 SKILL](../semantic-asset-export/SKILL.md)**；本高清校验器只检查PNG本身，不会核验它是否为**真正独立图标/独立背景**，也不会凭空补出HTML。该类交付同时执行 `scripts/verify_ui_delivery.py` 的语义资产与页面结构检查，**且应按用户认可金样与实际HTML浏览器截图执行 [分区视觉一致性检查](../../docs/ASSET_FIDELITY_REGRESSION.md)**。尺寸、透明度和文件结构合格，不能掩盖图标轮廓、立体底座、背景光影与还原效果不一致。

仓库提供可复用的**只读检查器**：`scripts/verify_ui_artifact.py`，需安装 Pillow（`python -m pip install Pillow`）。脚本不修改原图、不写回仓库；检查 PNG 解码、实际宽高、目标画布和（提供源图与允许区域时）**区域外像素差异**，退出码 0=自动检查通过，1=检查失败，2=参数错误。

```bash
# 新图尺寸/解码验证（不代表清晰度肉眼检查通过）
python scripts/verify_ui_artifact.py --image output.png --width 1920 --height 1080

# 局部修订：只允许改变 x=280,y=320,w=800,h=380，框外必须与认可基线完全一致
python scripts/verify_ui_artifact.py --image revised.png --before accepted.png --region 280,320,800,380 --width 1920 --height 1080 --require-change
```

脚本无源图时明确报告 `preservation_verified=false`，不能当作冻结验收。图像源尺寸不同、未提供合法允许修改框、框外变动、应修改却无变化、PNG无法解码、尺寸不符均拒绝通过。**脚本通过不代表设计审美、文字识别、业务、交互或实际用户下载通过**；仍必须人工核对。

**局部仅改一项时的新增验收**：不能只检查“非目标区域没有改动”，还必须检查**用户点名目标确实改了，且按要求方向改变**（如CONNECT下线变暗，而非变亮）。使用 [精准局部修改 SKILL](../precise-local-edit/SKILL.md) 的S0～S6和 [微变更方向/冻结检查器](../../scripts/verify_micro_edit.py)；HTML须核对最小CSS选择器/源码diff＋同视口浏览器截图。无改动、整页换色、基于错误版再改任何一项失败都不许宣布通过。

## 6. 交付前两项红线问题

- **清晰吗？** 是最终原尺寸成品、像素和细节真实清楚，还是聊天里的缩略预览/低清放大？不能确认就不称高清通过。
- **没乱改吧？** 能列出确切允许变更区以及未经修改的区域，且有源文件 diff 或实际图片对比吗？否则不称精准修改完成。

用户说“文字模糊、图片不清楚、你把别的也改了”时，直接记为未通过并退回最后认可版本修复；不要用新设计风格或调配色搪塞。**质量失败不是用户再提需求，而是设计师对原任务的纠错。**
